# 热更新与 Store 身份保持 · 源码精读

## 给 Writer 的教学钩子（必填，8 子项缺一不可）

- **用户痛点 / 场景**：开发者在改一个 store 文件（重命名某个动作、加一个计算属性、调整状态形状），保存后整页刷新会让所有已挂载组件丢失当前状态、重新走一遍挂载——开发反馈循环被生生拖慢。理想是「改完即时生效、组件无感、已修改的状态原样保留」。热更新机制要解决的就是这件事。

- **一句话核心思想**：**旧壳留着、只换里面的零件**——始终保持同一个 store 对象引用，把新定义的状态/计算属性/动作原地迁移进去。

- **设计动机（为什么需要它）**：组件在渲染期拿到的是 store 对象的引用，并长期持有；若热更新时换一个新对象，所有持有旧引用的组件都看不到新行为，必须整体重新挂载。于是 Pinia 选择「保持对象身份、原地改写内容」。其中两处是承前复用，Writer 注意去重：
  - 「用注册表登记 store、首次调用才懒创建」——（已在第 4 章『defineStore 的懒装配与循环引用破解』讲透，本章只看它的新侧面：热更新靠注册表里**已存在的旧实例**来锚定身份、判断该 store 是否曾被使用）。
  - 「组装引擎把 setup 返回的成员分类为状态/计算属性/动作」——（已在第 5 章『Setup Store 的运行时自动分流』讲透，本章只看它的新侧面：分类的同时顺手把每个成员的名字收集成一份**迁移清单**，供热更新比对谁该搬、谁该删）。

- **关键权衡（本 Atlas 的核心）**：
  1. **保持旧对象身份、原地迁移成员** → 换来组件无需重新挂载、订阅与已修改状态自然延续 → 代价是必须写一套「成员级」迁移逻辑：逐个搬运状态/计算属性/动作，还要 diff 出被删除的成员单独清理。
  2. **先用假身份建一个全新「影子实例」、再把它的零件嫁接到旧实例上** → 换来直接复用整套建店流水线（Options 与 Setup 两种风格自动各走各的分类路径，不必在热更新里重写一套）→ 代价是出现短暂的「双实例」开销，且必须事后清理影子实例在注册表与集中状态树里留下的临时痕迹，否则泄漏。
  3. **状态迁移按定义风格分叉：声明式风格递归合并、命令式风格整体搬运** → 换来两种风格下都不丢用户已修改的状态 → 代价是迁移逻辑必须区分风格（声明式状态形状预先已知、可按形状递归合并保住嵌套数据；命令式状态是散装的 ref、属性可运行时增减，递归合并反而会丢运行时新增的键，故只能整替）。
  4. **借构建工具在多次热更间持久化的数据槽，记住同一个容器实例** → 换来连续保存多次文件、容器与注册表始终稳定 → 代价是首次热更前得靠建店工厂上额外记的一个指针兜底，且一旦开发者改了 store 的 id，身份无法安全迁移、只能退化为整页刷新。

- **最小心智模型（6 步）**：
  1. 开发者在 store 文件里注册一个热更新回调，把「本文件导出的建店工厂」交给构建工具。
  2. 文件被编辑，构建工具热替换该模块，把新模块的全部导出交给回调。
  3. 回调从「跨次热更持久化的数据槽」（或首次建店时记下的兜底指针）找回唯一容器，确认旧 store 已在注册表中、且 id 未被改动。
  4. 回调用**旧 store 当作热参数**去调用新模块的建店工厂；工厂发现该 id 已存在便不再重建，而是用一个假 id 临时构建一个全新的影子实例。
  5. 在旧 store 上执行热更新：把影子实例的状态/计算属性/动作逐个搬来、删掉已不存在的成员、把集中状态树的对应槽位重新指向新状态，全程静音变更订阅以免误报。
  6. 删除影子实例的临时痕迹；旧 store 引用始终不变，组件无需重新挂载即可用上新逻辑。

- **最小原理演示（替代旧「复刻范围」）**：

## 概念要点

- **建店工厂的识别**：判断模块里某个导出是不是「建店工厂」，标准是「是函数 且 身上有字符串型 `$id`」。这是热更回调遍历新模块导出时区分 store 与普通工具函数的依据。源码位置: packages/pinia/src/hmr.ts:20-22

- **跨次热更保持同一容器**：优先从构建工具持久化数据槽读容器；读不到则回退到建店工厂身上记录的指针（该指针在 store 首次被创建时写下）。读到后立即写回数据槽，确保后续连续多次热更都能拿到同一个容器。源码位置: packages/pinia/src/hmr.ts:89-97；兜底指针写入: packages/pinia/src/store.ts:911-914

- **身份锚点 = 注册表里的旧实例**：遍历新模块每个导出，仅当「是建店工厂」且「其 id 在注册表中已存在」才处理——即只热更那些真正被使用过的 store；从未使用的 store 无需迁移（直接返回）。源码位置: packages/pinia/src/hmr.ts:100-103, 91-94

- **id 改变即不可安全迁移**：若新工厂的 id 与旧的不一致（开发者重命名了 store），无法把身份迁移到新 id，只能触发整页刷新并给出诊断。源码位置: packages/pinia/src/hmr.ts:107-111

- **热更新的入口手法**：把旧 store 实例作为「热参数」传给新工厂去调用——这一行是整套身份保持机制的命门。源码位置: packages/pinia/src/hmr.ts:113-118

- **「建影子再嫁接」策略**：新工厂被调用时发现该 id 已存在，便不再重建真 store，而是用一个加前缀的假 id 构建一个完整的新实例（影子），随即在旧 store 上触发热更新，最后把影子的临时痕迹从注册表与集中状态树里删干净。源码位置: packages/pinia/src/store.ts:919-930

- **成员清单（迁移比对依据）**：建店时额外维护一份被 `markRaw`（避免自身被响应式化）的清单对象，含 `actions`、`getters`、`state`（名字数组）与一个 `hotState` 状态桶。分流循环里按成员类型把名字登记进对应分组。热更新据此遍历「该搬谁」，并通过对比新旧清单的 key 发现「该删谁」。源码位置: packages/pinia/src/store.ts:424-429；收集于 store.ts:537（state）、549（actions）、558-561（getters）

- **热建店时的状态隔离桶**：热模式下不把状态写进真集中状态树，而是塞进一个独立的状态桶；新实例的 `$state` 读取器在热模式下返回这个桶。这让影子的状态与真 store 完全隔离，嫁接完再把真槽位指过来。源码位置: packages/pinia/src/store.ts:280, 511；`$state` 读取器: store.ts:583-584

- **状态迁移的双分支（核心分叉）**：遍历新清单中每个状态键，若旧 store 也有该键——声明式（Options）风格且新旧值都是普通对象时，递归合并（把旧用户数据合并进新形状）；否则（含命令式 Setup 风格）整体搬运旧值。源码内注释明确指出：命令式 store 的状态是散装 ref、属性可运行时增减，递归合并会丢失运行时新增的键（对应 issue #2611）。最后把旧 store 上的直接访问属性重指到新状态 ref。源码位置: packages/pinia/src/store.ts:602-628

- **递归合并工具**：跳过新形状里已不存在的键（这些键由「删除失效成员」环节另行清理）、双方均为普通对象则递归、否则整替；刻意只遍历字符串键（symbol 键无法序列化、不处理）。源码位置: packages/pinia/src/hmr.ts:33-62

- **集中状态树槽位重指**：把容器状态树上该 store 的槽位重新指向新清单里的状态桶。这让旧 store 的 `$state` 始终读到新内容，且集中状态树作为单一序列化源的契约不被破坏。源码位置: packages/pinia/src/store.ts:641

- **静音手法（复用变更管道的监听开关）**：重指槽位前先把两类监听开关关掉、重指后恢复（同步监听立即恢复、深度监听走 `nextTick`），避免这次「换底」被订阅当作一次普通变更事件。与 `$patch` 批量合并用的是同一套开关手法。源码位置: packages/pinia/src/store.ts:639-645；同手法见 $patch: store.ts:293, 316-321

- **动作/计算属性的迁移与删除**：遍历新清单的动作，用动作包裹器重新包一遍赋值给旧 store（使其保持可被动作订阅追踪）；计算属性在声明式风格下重新用计算属性包裹（确保互访时活跃指针正确）、命令式风格下直接赋值。最后对比新旧清单，删除旧有但新无的计算属性与动作。收尾把清单与 getter 列表整体替换为新版、清掉「热更新进行中」标志。源码位置: packages/pinia/src/store.ts:647-693

- **生产构建整块裁除**：非开发构建下，热更入口直接返回空函数；建影子、热更新方法、成员清单等逻辑全部被开发环境守卫包裹，生产包里不占体积。源码位置: packages/pinia/src/hmr.ts:84-87；store.ts 各处 `__DEV__` 守卫（如 599-694、919-930）

## 关键调用链

热更回调（拿到新模块）→ 找回容器（持久化数据槽优先 / 工厂指针兜底）→ 遍历新模块导出、命中已注册的旧 store → 用**旧 store 作热参数**调用新工厂 → 工厂走「id 已存在」热分支：建假身份影子实例 → 在旧 store 上触发热更新（状态逐键搬运 + 集中状态树槽位重指 + 动作重包 + 计算属性替换 + 删除失效成员 + 全程静音）→ 清理影子的临时痕迹。

源码位置: packages/pinia/src/hmr.ts:88-122（回调编排）；packages/pinia/src/store.ts:919-930（热分支：建影子 + 嫁接 + 清理）；packages/pinia/src/store.ts:600-693（热更新本体：成员级迁移）。
