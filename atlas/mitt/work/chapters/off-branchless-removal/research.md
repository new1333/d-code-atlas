# 无分支安全移除与重载清空 · 源码精读

## 给 Writer 的教学钩子（必填，8 子项缺一不可）

- **用户痛点 / 场景**：要从一堆监听器里「移除一个」时，最朴素的写法是先查它在不在、在才删——这一步天然带分支。而且「找不到」并不是异常情况：你完全可能去移除一个根本没注册过的处理器，或对一个从没注册过的类型调用移除。如果每条边界都写守卫，代码就膨胀了；对一款以「~200 字节」为卖点的库，每个分支、每个临时变量名都是实打实的体积成本。

- **一句话核心思想**：把「找不到」这个信号，用一个位运算直接抹平成「无害的越界下标」，让删除退化成一条无分支的直线。

- **设计动机（为什么需要它）**：移除这一动作里有两个本该需要分支的边界——(a) 处理器不在列表里（查找返回 -1），(b) 该类型压根没注册过。本章用一个位运算把 (a) 变成「必然越界、必然删零个」的安全动作，用一个外层真值判断把 (b) 变成整体 no-op，于是「移除」只剩两路：给了处理器就删一个、没给处理器就清空全部，没有第三路「找不到怎么办」。
  - 承前：本章建立在前置章『把 pubsub 退化成一张查找表』之上——移除方法只是对那张查找表的又一个读写者；查找表作为唯一状态、`string | symbol` 键、不做大小写归一化，均（已在第 1 章『把 pubsub 退化成一张查找表』讲透，本章只看删除侧如何以无分支方式读写这张表）。
  - 承前：本章「只删第一个匹配」是对前置章『惰性初始化的追加式订阅』刻意不去重的直接回应与对称——既然注册时不去重地追加，移除时也就一个一个地删，（已在第 3 章『惰性初始化的追加式订阅』讲透，本章只看删除侧如何与追加侧语义对称）。

- **关键权衡（核心原料）**：
  1. 「用一次无符号右移把查找返回的 -1 抹成一个巨大到必然越界的正整数 → 换来删除路径零分支、单行表达式、对压缩极度友好 → 代价是可读性骤降：读者必须同时知道『-1 经无符号右移会变成约 42.9 亿的正整数』和『数组删除方法会把越界起点钳制到长度、从而删零个』，两条冷知识缺一都会完全看不懂这一行在干嘛」。
  2. 「让省略处理器参数的重载表示『清空该类型全部处理器』 → 换来不必新增一个独立的清空方法、对外 API 表面更小 → 代价是同一个方法承担两种语义（删一个 / 清全部），仅靠参数个数区分，重载语义需文档点明」。
  3. 「清空时选择『把该类型的数组替换成空数组』而非『把该键从表里删掉』 → 换来类型键在表里始终存在、外部观察者（注册表是公开可窥探的）看到稳定的空数组而非 undefined → 代价是表会长期残留空数组键（反复清空多种类型时占内存），且这一『整体替换』风格与单条删除的『就地突变』风格不完全一致（推断）」。

- **最小心智模型（3～7 步）**：
  1. 拿到目标类型，去全局查找表里取出它的处理器数组。
  2. 若取不到（该类型从未注册），直接整体返回，什么都不做（安全 no-op）。
  3. 若给出了具体处理器：在数组里找出它第一次出现的位置。
  4. 把这个位置——包括「找不到」对应的 -1——经一次无符号右移，变成一个非负整数；找不到时会变成一个巨大到必然越界的数。
  5. 用这个数当起点删一个元素：越界时运行时会把起点钳制到数组长度、删除数量钳制为 0，等价于什么都没删。
  6. 若没给处理器：把该类型的数组整个替换成空数组，即清空该类型全部处理器。

- **最小原理演示（替代旧「复刻范围」）**：
  - 应演示：一个只表达「位运算抹平边界 + 重载清空」的极简移除方法，配一张查找表，几十行；每行对应上面某个原理点。它演的是权衡 1（无分支删除）与权衡 2（重载清空），以及权衡 3（清空=替换成空数组）。
  - 应故意省略：通配符 `'*'` 分支（属后续章）、Events 类型映射与泛型（属后续章）、与注册/派发的集成、symbol 键（机制完全等同 string 键，加了只增噪音）。
  - **演示载体建议：首选 TS/JS**。本章核心是「数值边界如何被位运算与数组删除语义抹平」，纯 TS/JS 即可忠实验透，配最小 `package.json` 即可 `node`/`bun run` 跑通；不涉及任何语言特有语义（无所有权/借用、无协程原语）、也不依赖宿主原生 API，故无须退回原仓库语言（TS）。下面给出可运行演示演的是哪条权衡：

  ```ts
  // 演：权衡1（无分支抹平 -1）+ 权衡2（省略参数=清空）+ 权衡3（清空=替换成空数组）
  type Handler = (e: unknown) => void;

  function makeOff(table: Map<string, Handler[]>) {
    return function off(type: string, handler?: Handler) {
      const list = table.get(type);
      if (!list) return;                       // 边界(b)：类型从未注册 -> 安全 no-op
      if (handler) {
        // 边界(a)：indexOf 找不到返回 -1；-1>>>0 = 4294967295（必然越界）
        // 数组删除方法会把越界起点钳到 length、删 0 个 -> 等价没删
        list.splice(list.indexOf(handler) >>> 0, 1);
      } else {
        table.set(type, [] as Handler[]);      // 重载：省略 handler = 清空该类型全部
      }
    };
  }

  // 执行轨迹
  const table = new Map<string, Handler[]>();
  const off = makeOff(table);
  const f: Handler = () => {};
  table.set('foo', [f, f]);   // 模拟注册两次（不去重）
  off('foo', f);              // 删第一个匹配 -> [f]
  off('foo', () => {});       // 删一个未注册的 -> 越界 -> 什么也不删 -> 仍 [f]
  off('foo');                 // 省略 handler -> 清空 -> []
  console.log(table.get('foo'), table.has('foo'));  // [] true（键仍在，值是空数组）
  ```

- **正文不宜展开的细节**：处理器参数的联合类型与内部存储靠 `as` 断言还原（属第 7 章『一张 Events 映射派生全 API 类型』）；`'*'` 通配符的移除重载签名（属第 6 章『通配符星号的第二条派发路径』）；外层用「真值判断」而非「显式判 undefined」来区分给没给处理器——因处理器恒为函数（恒真值），二者实际等价，点到即可；清空用「替换空数组」而非「原地截断」对外部已持有旧数组引用者的可见性差异（边角，脚注即可）。

- **推荐的一个执行轨迹例子**：初始查找表里 `foo → [f, f]`（同一函数被追加两次）→ 调「移除 foo 的 f」：位置=0，抹平后仍 0，删第一个 → `[f]` → 再调「移除 foo 的 g」（g 未注册）：位置=-1，抹平成 4294967295，越界钳制后删 0 个 → 仍 `[f]` → 调「移除 foo」（不带处理器）：走清空分支，替换成空数组 → `[]`，且 `foo` 键仍在表中。

## 概念要点

- 移除方法对外暴露两条重载：带处理器时删「一个」，不带处理器时清空「全部」。删除只删第一个匹配项，与注册侧的「不去重追加」严格对称（同一函数注册两次，要调两次移除才清干净）。源码位置: src/index.ts:29-33（接口重载）、test/index_test.ts:138-146（只删第一个匹配的测试）、test/index_test.ts:100-105（注册侧不去重的对照测试）。
- 「找不到」被无分支抹平：查找返回 -1 时，`-1 >>> 0 === 4294967295`；把它当起点传给 `splice`，按 ECMA-262 `actualStart = min(start, length)`、`deleteCount` 再钳为 `min(1, length - actualStart) = 0`，故删零个元素、原数组不变（已用 node 实测确认）。源码位置: src/index.ts:86。
- 「类型从未注册」被外层真值守卫抹平：`all.get(type)` 返回 undefined 时直接跳过整个方法体，既不抛错也不创建空键。源码位置: src/index.ts:83-84、90。
- 清空语义是「替换成空数组」而非「删除该键」：清空后 `all.get(type) === []`、`all.has(type) === true`（注册表对外公开可窥探，故此差异可被外部观测到）。源码位置: src/index.ts:88、test/index_test.ts:148-157。
- 不做大小写归一化：`'FOO'` 与 `'foo'`、`'baz:bat!'` 与 `'baz:baT!'` 是互不相干的键；对错误大小写的键调移除只会落到「类型从未注册」的 no-op 分支，不影响正确大小写的键（测试里对 `baz:baT!` 调移除后，`baz:bat!` 仍有 1 个处理器）。源码位置: test/index_test.ts:121-136。
- 移除方法从不抛异常（无分支 + 真值守卫的双重保证），这是它能在派发进行中被处理器安全调用的前提——但「调用后是否影响当前正在进行的派发」属下一章「快照式派发」的范畴，本章不展开。源码位置: src/index.ts:82-91。

## 关键调用链

外部调用 `off(type, handler?)`
  → `all.get(type)` 取该类型处理器数组（复用第 1 章的查找表状态）
    → 取不到 → 整体 no-op（边界 b）
    → 取到：
        → 给了 handler → `handlers.indexOf(handler) >>> 0` → `handlers.splice(_, 1)`（边界 a 在此被抹平）
        → 没给 handler → `all.set(type, [])`（重载清空）

与注册方法的对称关系（跨章调用链）：`on` 不去重地 push（第 3 章）→ 同一函数可出现多次 → `off` 靠 `indexOf` 只取首个、一次删一个 → 二者语义对称。
源码位置: src/index.ts:82-91（off）、src/index.ts:66-73（on 对照）。

移除方法实现——整章灵魂所在的无分支单行：
```ts
// src/index.ts:82-91
off<Key extends keyof Events>(type: Key, handler?: GenericEventHandler) {
	const handlers: Array<GenericEventHandler> | undefined = all!.get(type);
	if (handlers) {
		if (handler) {
			handlers.splice(handlers.indexOf(handler) >>> 0, 1);
		} else {
			all!.set(type, []);
		}
	}
}
```

## 易混淆 / 边界 / 推断

- **事实**：`off(type)` 清空后留下空数组、键仍在表里（`has` 为 true），不是「删键」。这是测试明文断言的可观测契约。源码位置: test/index_test.ts:148-157、src/index.ts:88。
- **事实**：删除只删「第一个」匹配——`indexOf` 取首次出现位置；与注册侧不去重对称，要对同一函数调 N 次移除才能清掉 N 次注册。源码位置: test/index_test.ts:138-146。
- **事实**：外层用 `if (handler)` 真值判断区分两路。处理器恒为函数（恒真值），故等价于 `handler !== undefined`；但若有人传入 `null`/`0` 等假值，也会被当作「没给处理器」走清空分支——不过类型签名上处理器只能是函数，实际不可触发。源码位置: src/index.ts:85。
- **推断（标注为推断）**：清空选 `set(type, [])`（整体替换）而非 `handlers.length = 0`（原地截断），可能意在「不惊动外部已持有旧数组引用者」——替换后旧引用仍保留原内容、表内则指向新空数组；但这只是从代码风格反推的合理猜测，源码与注释未明说。
- **推断（标注为推断）**：选 `>>> 0` 而非 `if (i >= 0)` 的首要动机是体积（~200b 卖点）与压缩友好度，而非性能；位运算省下的几个字节在 gzip 后收益有限，但契合库的极简定位。
- **边界（类型与运行时不对称）**：通配符 `'*'` 的移除重载在类型层只声明了「必须带处理器」一条（`off(type: '*', handler: ...)`），但运行时方法体是共享的——理论上 `off('*')` 不带处理器也会清空全部通配处理器，只是类型层没暴露这条重载。此为后续通配符章的伏笔，本章不展开。源码位置: src/index.ts:33。
- **未理解**：无。本方法体仅 9 行，逻辑已完全厘清并由测试与 node 实测双重确认。
