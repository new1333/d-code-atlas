# 惰性初始化的追加式订阅 · 源码精读

## 给 Writer 的教学钩子（必填，8 子项缺一不可）

- **用户痛点 / 场景**：在一个发布订阅库里，使用者最常做的事就是「往某类事件上挂处理器」。如果没有一条清晰的写入策略，常见陷阱有两个：一是哪怕没人监听某类事件，库也提前为它占着内存；二是同一处理器被不小心挂了两次，触发时只响一次（或反过来响两次却没人料到）。使用者需要的是一条「什么时候建表、要不要查重」都讲死了、可预测的规则。

- **一句话核心思想**：**先查表里有没有这一类，没有才建表，有就往后追加——并且永远不查重。** 这是全章灵魂句。

- **设计动机（为什么需要它）**：上一章已经把整个发射器的状态退化成「一张『类型 → 处理器数组』的查找表」（已在第 1 章『把 pubsub 退化成一张查找表』讲透）。本章只看它的下一个动作——**往这张表里写一个处理器时，用哪种写入策略**。具体只盯两个选择：数组什么时候才分配内存（惰性 vs 预分配）、以及写入时要不要排除重复（追加 vs 去重）。

- **关键权衡（本 Atlas 的核心）**：
  1. **惰性建表，而非预先为每个类型分配空数组** → 做了「只在某类型第一个处理器到来时才为它创建数组」的选择 → 换来了表里只出现真正有人监听的类型键、未监听类型零内存零开销、派发时一次查询拿到『空』即可快速短路 → 代价是每次注册都得先查一次表做存在性判断（一次查询 + 一个分支）。
  2. **追加而不查重，对齐 Node 事件发射器语义** → 做了「拿到已存在的数组就直接往末尾放、不做『是否已含同一函数』检查」的选择 → 换来了注册路径 O(1) 且无遍历、代码最短、语义完全可预测（注册几次就触发几次） → 代价是把去重责任甩给调用方——重复注册同一函数会在派发时被多次调用，是常见误用源。
  3. **用『查到的值』本身做存在性判断，而非『先问有没有再取』** → 做了「直接拿一次查询的返回值（数组对象 or 空）的真假来分支」的选择 → 换来了一次查询同时回答『这个类型存在吗』和『把数组给我』两件事，省掉一次冗余查询 → 代价是依赖『数组对象恒为真值』这一不变式；本库永远不为已存在的键存入会判假的值（即便清空也只是存一个空数组对象，仍为真），故不变式成立。

- **最小心智模型（3～7 步）**：
  1. 一次注册调用到来，带着「类型」和「处理器」两个参数。
  2. 向唯一状态（那张查找表）查这个类型当前对应的数组。
  3. 若查到的是一个已存在的数组 → 把处理器追加到末尾，注册顺序被保留。
  4. 若查到的是「没有」（该类型头一回被注册）→ 新建一个只含此处理器的数组，登记进表。
  5. 全程不检查这个处理器是否已经登记过——同一处理器可重复出现。
  6. 净效果：表里每个被注册过的类型，都持有「按注册顺序排列、允许重复」的处理器序列。

- **最小原理演示（替代旧"复刻范围"）**：
  - 应演示：一个**小到只表达核心思想**的从零实现（几十行），每一行对应上面某个原理点。它演的是**权衡 1（惰性建表）+ 权衡 2（追加不去重）**这两条。
  - 应故意省略：通配符派发、移除、类型泛型与断言、symbol 私有频道、可注入的共享表、派发逻辑本身。
  - **演示载体建议：首选 TS/JS**。本章核心是「往一个 Map 里写入时的策略」——纯数据结构与写入语义，TS/JS 完全能忠实演透，且本就是 JS 生态库，读者最易跑通（配最小 `package.json`，`node`/`bun run` 即可）。无需退回原仓库语言。
  - 演示骨架（供 Writer 落地）：
    ```js
    const table = new Map();                 // 唯一状态：类型 -> 处理器数组
    function on(type, handler) {
      const list = table.get(type);          // 一次查询，同时承担「存在吗」+「给我数组」
      if (list) {
        list.push(handler);                  // 权衡2：已有数组就追加，不查重
      } else {
        table.set(type, [handler]);          // 权衡1：首次注册才建表
      }
    }
    // 断言演示：
    on('foo', h1); on('foo', h2); on('foo', h1);
    // table.get('foo') === [h1, h2, h1]   ← 追加保序 + 同一函数不去重
    // table.has('bar') === false          ← 从未注册的类型零占用
    ```

- **正文不宜展开的细节**：注册方法的泛型签名 `Key extends keyof Events` 与内部「联合处理器类型 + `as` 断言」——属第 6 章『一张 Events 映射派生全 API 类型』；通配符 `*` 在注册端并无特殊待遇，只是又一个会被惰性建表的普通键，其特殊性全在派发端——属第 5 章；事件类型允许 `symbol`、不做大小写归一化——已在第 1 章讲透，本章只是受益者（注册对任意 string/symbol 键一视同仁）；`all` 对外公开可变、工厂式无 `this`——属第 2 章。

- **推荐的一个执行轨迹例子**：输入是一张刚建好的空表。
  - 注册(foo, h1) → 查 foo 得「空」→ 建表 `[h1]`
  - 注册(foo, h2) → 查 foo 得 `[h1]`（真值）→ 追加 → `[h1, h2]`
  - 注册(foo, h1) → 查 foo 得 `[h1,h2]` → 追加（不查重）→ `[h1, h2, h1]`
  - 输出：之后派发 foo，会按 `[h1,h2,h1]` 顺序触发三次，其中 h1 被叫两次。

## 概念要点
- **写入分两支，分支依据是『查到的值是否为真』**：先 `all.get(type)` 取当前数组；拿到数组对象就走追加支，拿到 `undefined`（类型从未注册过）就走建表支。源码位置: src/index.ts:66-72
- **建表支只发生在「首次」**：`else` 分支 `all.set(type, [handler])` 把唯一处理器包进新数组登记入表；此后的同类型注册永远走 `if` 支。源码位置: src/index.ts:70-72
- **追加支是 O(1) 末尾插入**：`handlers.push(handler)`，保留注册顺序，不做任何存在性/重复检查。源码位置: src/index.ts:68-69
- **刻意不去重，且这是明文契约**：测试注释直接引用 Node.js EventEmitter 的 `on` 语义作为对齐依据——同一函数多次注册应被登记多次。源码位置: test/index_test.ts:98-105
- **注册端对键名零限制**：连 `'constructor'` 这类原型属性名也被当普通键直接登记（因状态用 `Map` 而非普通对象，无原型污染），验证了「任意 string 键一视同仁」。源码位置: test/index_test.ts:63-68
- **一次查询承担两件事**：用 `get` 的返回值真假分支，而非先 `has` 再 `get`，省一次 map 查询（无源码注释，依代码结构推断为推断）。源码位置: src/index.ts:67-68

## 关键调用链
注册(type, handler)
  → all.get(type)                      // 查当前类型的数组
  → 分支：
     ├─ 已有数组（真值） → handlers.push(handler)          // 追加，保序，不去重
     └─ undefined（首次） → all.set(type, [handler])       // 建表
源码位置: src/index.ts:66-72

## 源码摘录（带行号，全文累计 ≤ 30 行）
注册方法本体（两条分支 = 权衡 1 + 权衡 2 的落点）：
```ts
// src/index.ts:66-73
on<Key extends keyof Events>(type: Key, handler: GenericEventHandler) {
	const handlers: Array<GenericEventHandler> | undefined = all!.get(type);
	if (handlers) {
		handlers.push(handler);
	} else {
		all!.set(type, [handler] as EventHandlerList<Events[keyof Events]>);
	}
},
```

## 易混淆 / 边界 / 推断
- **事实**：注册同一函数 N 次，表中就出现 N 次，派发时该函数被调用 N 次；去重须由调用方自行保证（如先 off 再 on）。源码位置: test/index_test.ts:100-105
- **事实**：清空某类型用的是 `all.set(type, [])`（设空数组）而非 `delete`，键仍留在表里；因此清空后再注册，会走「追加支」push 到这个空数组（行为正确，不重建表）——但该机制属下一章移除/清空范畴，本章仅记录其对注册路径的无害影响。源码位置: src/index.ts:88
- **推断（标注为推断）**：用 `get` 返回值的真假而非 `has`+`get` 来分支，意在省一次 map 查询；源码无注释说明，依实现结构推断。
- **推断（标注为推断）**：「不查重」并非疏忽，而是刻意的语义对齐（测试注释引用 Node 文档为证），用以换取最小代码与可预测语义。
- **未理解**：无。
