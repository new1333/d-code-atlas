# 把 pubsub 退化成一张查找表 · 源码精读

## 给 Writer 的教学钩子（必填，8 子项缺一不可）

- **用户痛点 / 场景**：成熟的发布订阅库（如 Node 的 EventEmitter）往往带着一整套隐式状态——优先级队列、`once` 标记、异步调度、监听器上限警告、内部 Symbol 钩子……使用者既看不全它内部到底记了什么，也难以把它的状态整个 dump 出来调试；想做一个「我只是要在两个模块之间传个事件」的极简场景，却被裹挟进一个又重又黑盒的对象。本章要解决的，就是「事件总线能不能小到只剩一张表、且完全透明」这个矛盾。

- **一句话核心思想**：把发布订阅的全部状态，坍缩成一张「事件类型 → 处理器数组」的查找表——除此之外，发射器没有任何别的内部状态。

- **设计动机（为什么需要它）**：这个机制是为了对抗「传统 emitter 又重又黑盒」而生的，它换来的核心能力是**极简（声称压缩后约 200 字节）**与**完全可窥探**（这张表是实例上的公开字段，直接打印就能看见全部订阅关系）。它是全书地基，后续每一章都是「在这张表上做某个具体操作」——订阅的具体写法、退订的位运算技巧、发布的快照防御、通配符的第二派发路径——都建立在本章确立的「表即状态」之上。其中**「这张表被公开为实例字段、且可从外部注入共享」这一封装取舍，主要属于第 2 章『函数工厂与无 this 的方法』的核心权衡（已在第 2 章讲透，本章只看它作为「唯一状态容器」的这一侧面，不去演注入与共享）**；本章只负责把「状态 = 一张查找表」这个地基立起来。

- **关键权衡（本 Atlas 的核心）**：
  1. **状态形态选择**：让一张「类型→处理器数组」的映射表成为发射器的**唯一**状态（而不是用类的多个实例字段、或优先级队列等富结构）→ 换来了：整个发射器能用一句话描述、能被 `console` 直接打印窥探、代码体积压到最小 → 代价是：**放弃封装**，这张表对任何拿到实例的人都完全公开且可变（谁都能直接改表）。
  2. **键的语义选择**：事件类型只接受字符串与 symbol 两种、且**刻意不做任何归一化**（不 `toLowerCase`、不去空白）→ 换来了：精确匹配的语义完全可预测，外加 symbol 天然形成「私有频道」——外部拿不到某个 symbol 引用就永远无法监听它 → 代价是：键的一致性责任全部转嫁给调用方，`'FOO'` 与 `'foo'` 是两个互不相干的事件，这是设计而非缺陷。
  3. **处理器集合的选择**：某类型的处理器集合就是一个**普通数组**，不内置优先级、不内置 `once`、不内置异步队列 → 换来了：极小体积与完全透明的状态语义 → 代价是：放弃这些高级能力，需要它们时调用方得自己在处理器里实现（例如「只触发一次」= 处理器在执行体内自行把自己从表里退订）。

- **最小心智模型（3～7 步）**：
  1. 创建一个发射器时，若没从外部传入一张已存在的表，就新建一张空的映射表。
  2. 这张表的每一条记录都是「一个事件类型 → 一组处理器」。
  3. **订阅** = 查表：该类型已有数组就往里追加一个函数，没有就新建一条记录。
  4. **退订** = 查表：从对应数组里移除那个函数；若连函数参数都省略，就把该类型的数组整个清空。
  5. **发布** = 查表两次：先取出该类型的数组逐个调用，再取出通配符那组逐个调用（通配符的细节留给后续章）。
  6. 全程没有任何隐藏的第二个状态——**表就是发射器的全部**，看见这张表就等于看见了发射器的完整状态。

- **最小原理演示（替代旧「复刻范围」）**：
  - **应演示**：一个**小到只表达「状态即一张查找表」**的从零实现（三四十行即可）。它要把发射器写成「围绕一张映射表的增、删、查、调」，每一行都要对应上面的某个原理点——具体说就是演透权衡 1（唯一状态）与权衡 3（处理器就是裸数组）：订阅=往表里塞、发布=从表里取出来遍历调用。演示里要让读者亲眼看到「**整个 emitter 对象除了这张表，什么都没有**」。
  - **应故意省略**：通配符 `'*'` 的第二条派发路径（第 6 章）、发布时的 `.slice()` 快照防御（第 5 章）、退订时的 `>>> 0` 无分支技巧（第 4 章）、订阅时的「首个处理器才建数组」惰性细节（第 3 章）、可注入共享表与无 `this` 工厂（第 2 章）、以及任何 TS 类型推导（第 7～8 章）。本章演示就该用**最朴素**的写法——普通 `if` + `push`、普通 `splice`、普通 `for` 循环遍历——不为体积/技巧做任何优化，**唯一目的是把「表 = 全部状态」演透**。演示里建议显式 `console.log(emitter)` 或打印这张表，让「可窥探」这个能力被读者直接看见。
  - **演示载体建议**：**首选 TS/JS**。本章核心是「数据结构选型 + 三步 CRUD」，属于纯数据结构/算法范畴，TS/JS 完全能忠实演透；且本 Atlas 产物本身是 JS 生态的 VitePress 站点，TS/JS 演示配最小 `package.json` 即可 `bun run`/`node` 跑通，对读者最友好。**无需退回原仓库语言**（原仓库本就是 TS，恰好同构）。一句话原则：载体服务于「演透原理」，本章毫无理由用别的语言。

- **正文不宜展开的细节**：类型层的 `Events extends Record<EventType, unknown>` 约束与 `keyof Events` 反向派生（第 7 章）；通配符 `'*'` 作为保留键与双参签名、以及为何禁止手动 `emit('*')`（第 6 章）；发布时的 `.slice()` 快照（第 5 章）；退订的 `indexOf(...) >>> 0` 位运算与「省略 handler = 清空」重载（第 4 章）；`on` 的惰性初始化与不去重语义（第 3 章）；`mitt()` 作为函数工厂、`all` 可注入、方法不依赖 `this`（第 2 章）；以及 `Handler`/`WildcardHandler` 的泛型默认值 `unknown` 这类类型边角。

- **推荐的一个执行轨迹例子**：
  - 输入：对某发射器先 `订阅('foo', a)`、`订阅('foo', b)`，再 `发布('foo', 42)`。
  - 关键中间态：表的内容为 `'foo' → [a, b]`；发布时查表得到这个数组。
  - 输出：依次调用 `a(42)`、`b(42)`；**发布前后表本身不变**（这是「状态即表」最朴素的证明：派发只是读表，不改表）。

## 概念要点

- **事件类型的全集定义**：`EventType = string | symbol`，事件类型只能是字符串或 symbol 两种；这是整张表 key 的取值域。源码位置: src/index.ts:1
- **单事件处理器签名**：`Handler<T> = (event: T) => void`——一个处理器只接收一个 event 参数、无返回值；`event` 即载荷。源码位置: src/index.ts:5
- **「某类型的处理器集合」就是普通数组**：`EventHandlerList<T> = Array<Handler<T>>`，没有封装成优先级队列或 Set，就是原生 `Array`。源码位置: src/index.ts:12
- **整个发射器的状态类型 = 一张映射表**：`EventHandlerMap<Events> = Map<keyof Events | '*', EventHandlerList | WildcardHandlerList>`——状态的形态就是 `Map`，值是「处理器数组」。源码位置: src/index.ts:18-21
- **状态是实例上的公开字段**：`Emitter` 接口里 `all: EventHandlerMap<Events>` 直接作为 public 字段暴露，未做 `readonly` 或私有化保护。源码位置: src/index.ts:24
- **状态的初始化逻辑**：`all = all || new Map()`——传入则共享同一张表，否则新建空表。源码位置: src/index.ts:52
- **三件事都只读写这一张表、别无其它状态**：`on`/`off`/`emit` 全部通过对 `all` 的 `get`/`set`/数组操作完成；返回的对象字面量除 `all` 外只有三个方法，没有任何额外实例字段。源码位置: src/index.ts:54-122
- **刻意不归一化**：全文没有任何 `toLowerCase`/`trim` 等键归一化代码，key 严格按相等性匹配——`'FOO'` 与 `'foo'` 是两个独立条目。源码位置: src/index.ts:1,66,103（全文无归一化）

## 关键调用链

状态生命周期（一切围绕单张表）：

- 创建：`mitt(all?)` → `all = all || new Map()` → 返回 `{ all, on, off, emit }`。源码位置: src/index.ts:46-54
- `on(type, h)`：`all.get(type)` → 命中则 `push(h)`；未命中则 `all.set(type, [h])`。源码位置: src/index.ts:66-73
- `off(type, h)`：`all.get(type)` → 给了 h 则 `splice` 移除；省略 h 则 `all.set(type, [])` 清空。源码位置: src/index.ts:82-91
- `emit(type, evt)`：`all.get(type)` 取出快照遍历调用 → 再 `all.get('*')` 取出通配数组遍历调用。源码位置: src/index.ts:103-121

> 即：`on/off/emit` 三者都只是「对同一张表的 get/set + 数组操作」，表是唯一的状态中介。

## 源码摘录（带行号，全文累计 ≤ 30 行）

状态结构定义（这是「表 = Map<类型, 处理器数组>」的字面体现）：

```ts
// src/index.ts:1,5,12,18-21
export type EventType = string | symbol;
export type Handler<T = unknown> = (event: T) => void;
export type EventHandlerList<T = unknown> = Array<Handler<T>>;
export type EventHandlerMap<Events extends Record<EventType, unknown>> = Map<
	keyof Events | '*',
	EventHandlerList<Events[keyof Events]> | WildCardEventHandlerList<Events>
>;
```

`all` 是实例上唯一字段，且对外公开（未私有化）：

```ts
// src/index.ts:24,52
all: EventHandlerMap<Events>;   // Emitter 接口：唯一状态，public
...
all = all || new Map();          // 工厂内：传入则共享，否则新建空表
```

`on` / `emit` 如何操作这张表（体现「派发=读表、订阅=写表」）：

```ts
// src/index.ts:66-73  on：查表 → 有则追加，无则建条目
const handlers = all!.get(type);
if (handlers) handlers.push(handler);
else all!.set(type, [handler]);

// src/index.ts:104-110  emit：查表 → 取数组逐个调用（slice 快照见第5章）
let handlers = all!.get(type);
if (handlers) (handlers as EventHandlerList<...>).slice().map(h => h(evt!));
```

## 易混淆 / 边界 / 推断

- **事实**：`all` 是 emitter 上唯一的可变状态字段，且未用 `readonly`/`#` 私有化，任何拿到实例的代码都能 `emitter.all.get(...)`/`emitter.all.set(...)` 直接改表——「可窥探」与「可被外部篡改」是一体两面。源码位置: src/index.ts:24,58
- **事实**：表中所有处理器（普通 + 通配符）统一以联合类型 `GenericEventHandler` 存储，运行时无法从表本身区分一个处理器是普通还是通配符；区分只发生在 `emit` 时按 key 是否等于 `'*'` 决定调用签名。源码位置: src/index.ts:49-51,113-119
- **事实**：`'FOO'` 与 `'foo'` 是两个互不相干的 key，刻意不归一化——精确匹配是 feature。源码位置: 全文无归一化；README 同样未提及大小写处理。
- **推断（标注为推断）**：选用 `Map` 而非裸对象 `{}` 承载状态，推断动机有三：(a) `Map` 原生支持 symbol 作 key（裸对象虽也能用 symbol key，但字符串 key 易撞原型链、需 `Object.create(null)` 规避）；(b) `Map` 无原型链污染风险；(c) `Map` 的迭代顺序 = 插入顺序，遍历可预测。源码未留注释说明此选择，故为推断。源码位置: src/index.ts:18,52
- **推断**：整个文件 ~120 行、声称 ~200b（min+gzip），把 `on/off/emit` 全部内联在返回对象字面量里、共享同一个 `all` 闭包变量——这是「最小体积」目标的直接体现，也解释了为何状态只有一个字段。源码位置: src/index.ts:42,54-122
- **未理解**：无。本文件机制清晰，无需保留未解之谜。
