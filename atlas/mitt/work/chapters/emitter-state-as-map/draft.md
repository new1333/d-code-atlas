# 把 pubsub 退化成一张查找表

如果你写过 Node 后端，或者在前端用过 `addEventListener`，那你八成碰过 `EventEmitter` 这类东西。它很能干——能设监听器优先级、能标记「只触发一次」、能在监听器太多时报警、还能异步派发。能力一长串，状态也跟着一大堆。

可现实里，你十有八九只是想做这么一件事：**A 模块喊一嗓子「数据好了」，B 模块听见了去做点事**。为了这一嗓子，你 new 了一个 EventEmitter，结果它肚子里塞着优先级队列、内部 Symbol 钩子、各种计数器……你想看一眼「我到底注册了哪些监听器」，得专门去翻它的 API，还看不全内部到底记了什么。

mitt 想把这件事整个翻过来：**剥掉所有花活，让一个事件发射器小到只剩一张表**。这张表就是它的全部家当，你 `console.log` 一下，所有订阅关系一览无余。这一章我们就来把这张表从无到有搭起来。

## 先认识两块最小的积木

搭表之前，先看清两样最底层的东西。

**第一块：事件类型，就是一个名字。** 它只能是字符串或 symbol——要么是一段文本（比如 `'data-ready'`），要么是一个 symbol。你可以把它理解成一个**频道名**：谁要听这个频道，就盯着这个名字。

```js
// 事件类型全集：要么字符串，要么 symbol
'login'            // 字符串频道
Symbol('secret')   // symbol 频道
```

**第二块：处理器，就是一个收数据的函数。** 它长这样：拿到一份事件数据，做点事，不返回值。频道里一旦有动静，所有盯着它的处理器就会被挨个叫起来，把这份「事件携带的数据」递给它们。

```js
// 处理器：收一份事件数据，干完拉倒
const onLogin = (user) => {
  console.log('欢迎', user.name)
}
```

就这两块。没有类、没有继承、没有调度器。一个**名字**，加一个**收到数据就干活的函数**。

## 把同一频道的处理器装进一个数组

一个频道通常不止一个人在听。`'login'` 这个频道，可能既有人负责写日志，也有人负责发欢迎邮件。所以每个频道底下，得有个东西把这些处理器都装起来。

mitt 的选择简单到有点愣：**就用一个普通数组**。不封装成带优先级的队列，不用 `Set` 去重，就是个原生 `Array`。

```js
// 'login' 频道下的处理器们，就是一个数组
const loginHandlers = [writeLog, sendWelcomeEmail]
```

为什么这么「裸」？因为这一章的目标就是透明——数组是什么样，表里就是什么样，没有任何中间层替你做决定。

## 立地基：一张表装下所有频道

把上一节的「频道 → 处理器数组」复制很多份，每份对应一个频道，再找个东西把它们全收在一起。mitt 用的就是这个：

```
Map {
  'login'   => [写日志, 发欢迎邮件],
  'logout'  => [清缓存],
  Symbol()  => [内部审计],
}
```

一个 `Map`，键是事件类型（频道名），值是这个频道下的处理器数组。**这就是发射器的全部状态**——除此之外，发射器里再没有第二个东西藏着。

把这张表想象成一块**公共留言板**：每个频道是板上的一块分区，分区的名字就是频道名，分区里钉着一张纸条，纸条上列着一串「听到动静要做的事」。谁来都能看见整块板。

## 三步走完所有操作：订阅、发布、退订

发射器一辈子就干这三件事，而且**每一件都只是在读写这块留言板**。

**订阅（on）= 往表里塞一条**：先查表里有没有这个频道。有，就把新处理器 push 进它的数组；没有，就给它新开一条记录。

```
订阅('login', 发欢迎邮件)
  → 查表：'login' 在不在？
     ├─ 在  → [写日志].push(发欢迎邮件) → [写日志, 发欢迎邮件]
     └─ 不在 → 表里新开一条 'login' => [发欢迎邮件]
```

**发布（emit）= 从表里取出来逐个叫醒**：查表拿到这个频道的处理器数组，从头到尾挨个调用，把事件数据递给每一个。注意——发布**只是读表**，表本身一个字都没改。

```
发布('login', { name: '小明' })
  → 查表：拿到 [写日志, 发欢迎邮件]
  → 逐个调用：写日志({name:'小明'})，发欢迎邮件({name:'小明'})
  → 表的内容纹丝不动
```

**退订（off）= 从表里抹掉一条**：查表拿到数组，把那个处理器从数组里移除。

```
退订('login', 发欢迎邮件)
  → 查表：拿到 [写日志, 发欢迎邮件]
  → 移除「发欢迎邮件」→ [写日志]
```

看出门道了吗？三件事都围着同一张表转。没有别的状态，没有隐藏的副本。这块板，就是发射器的身份证。

## 亲手写一个：从零实现

下面是从零写的最小实现，三十来行，每一行都对应上面的某个动作。我故意用最朴素的写法——普通 `if`、普通 `push`、普通 `splice`、普通 `for`——不为任何体积或技巧做优化，唯一目的就是让你看清「表就是全部」。

```js
// emitter.mjs —— 存成文件后 `node emitter.mjs` 即可运行

function createEmitter() {
  // ① 这张表，就是发射器的全部状态
  const all = new Map();

  return {
    // ② 把表公开出来：任何拿到发射器的人，都能直接看、直接改它
    all,

    // ③ 订阅 = 写表：表里有这个频道就追加，没有就开一条新记录
    on(type, handler) {
      const handlers = all.get(type);
      if (handlers) {
        handlers.push(handler);
      } else {
        all.set(type, [handler]);
      }
    },

    // ④ 退订 = 删表：从频道的数组里抹掉这个处理器
    off(type, handler) {
      const handlers = all.get(type);
      if (handlers) {
        const i = handlers.indexOf(handler);
        if (i !== -1) handlers.splice(i, 1);
      }
    },

    // ⑤ 发布 = 读表：取数组，从头到尾挨个调用
    emit(type, evt) {
      const handlers = all.get(type);
      if (handlers) {
        for (const h of handlers) h(evt);
      }
    },
  };
}
```

跑一段场景看看（对应心智模型里的执行轨迹）：

```js
const emitter = createEmitter();

const a = (n) => console.log('a 收到', n);
const b = (n) => console.log('b 收到', n);

emitter.on('foo', a);
emitter.on('foo', b);

// 「可窥探」直接兑现：打印发射器，就看见了全部订阅关系
console.log(emitter.all);
// => Map { 'foo' => [ [Function a], [Function b] ] }

emitter.emit('foo', 42);
// => a 收到 42
// => b 收到 42

// 发布只是读表，发完再看，表一个字没变
console.log(emitter.all);
// => Map { 'foo' => [ [Function a], [Function b] ] }   ← 还是它
```

最后一行是整章最关键的一句：**发布前后，表没有任何变化**。这就是「状态即一张表」最朴素的证明——派发纯粹是在读表，不产生任何新状态。

## 关键权衡：为了「小到只剩一张表」，砍掉了什么

原理演示只用了三十来行，但 mitt 真正值钱的是它**主动放弃**的那些东西。下面三条权衡，每一条都是「做了 X 选择 → 换来了 Y → 代价是 Z」。

### 权衡一：让一张 Map 成为唯一状态

**选择**：发射器的全部状态就是一张 `Map<事件类型, 处理器数组>`，没有第二个字段、没有优先级队列、没有调度器、没有任何富结构。

**换来**：整个发射器能用一句话描述完——「它就是一张表」；这张表能被 `console.log` 直接打印，所有订阅关系一目了然；代码体积因此压到极致（mitt 宣称压缩后约 200 字节）。

顺带一提，这里选 `Map` 而不是普通对象 `{}` 来当这张表，是有道理的：`Map` 能直接拿 symbol 当键、没有原型链污染的隐患、而且遍历顺序就等于你插入的顺序，状态可预测。（这是从设计反推的判断，源码没留注释明说。）

**代价**：放弃封装。这张表对任何拿到发射器的人都完全公开、完全可变——谁都能 `emitter.all.get(...)` 偷看，也能 `emitter.all.set(...)` 直接改。「能窥探」和「能被随便篡改」在这里是一体两面。至于 mitt 为什么索性把它做成实例上的公开字段、甚至允许从外部塞一张表进来共享——这是**下一章《函数工厂与无 this 的方法》**专门要展开的取舍，本章只把「唯一状态容器」这一面立起来，先不展开它。

### 权衡二：事件类型刻意不做标准化

**选择**：事件类型只接受字符串和 symbol，且**刻意不去标准化**它——不转小写、不去空格、不做任何格式统一。

**换来**：精确匹配的语义完全可预测。你注册的是 `'foo'`，就只有 `emit('foo')` 能叫醒它，所见即所得，没有任何「暗中帮你做了转换」的意外。

更妙的是 symbol 带来的副产品：**天然形成私有频道**。你把一个 `Symbol()` 当频道名，只要这个 symbol 的引用没泄露出去，外部代码就永远没法订阅或触发这个频道——它就像一把**只有你持有的钥匙**，没钥匙的人连频道名都喊不出来，更别说监听了。靠这种语言特性白捡了一个隔离机制。

**代价**：键的一致性责任被整个甩给了调用方。`'FOO'` 和 `'foo'` 在 mitt 眼里是两个互不相干的频道，注册 `'FOO'` 却去 `emit('foo')`，不会报错，就是没人理你。这不是 bug，是写进基因里的设计——它换来了上面那份「绝不偷偷帮你转换」的可预测性。

### 权衡三：处理器集合就是裸数组

**选择**：每个频道下的处理器，就是一个普通 `Array`，不内置优先级、不内置 `once`（只触发一次）、不内置异步队列。

**换来**：极小的体积，加上完全透明的状态语义——表里写的什么，运行时就按什么跑，没有任何隐藏的调度层替你重新排序或延迟。

**代价**：主动放弃了一堆传统 emitter 开箱即用的能力。想要这些，调用方得自己在处理器里实现。比如「只触发一次」，在这里没有一个 `once` 参数，你得让处理器在执行体里**自己把自己从表里退订**：

```js
const once = (type, handler) => {
  const wrapper = (evt) => {
    handler(evt);        // 先干正事
    emitter.off(type, wrapper);  // 再把自己摘掉
  };
  emitter.on(type, wrapper);
};
```

换句话说，mitt 把「需不需要这些高级能力」这个决定权，连同实现成本，一起交还给了你。多数场景下你根本用不上它们，也就根本不用为它们付任何代价。

## 小结

这一章我们立起了一块地基：**一个事件发射器，可以小到只剩一张 `Map<事件类型, 处理器数组>`**。

- 三块积木：事件类型（`string | symbol`）、处理器（收数据的函数）、装处理器的数组；
- 一个容器：一张 `Map`，是发射器的**唯一**状态；
- 三步操作：订阅写表、发布读表、退订删表——全都围着这一张表转，别无其它状态。

围绕「把状态压成一张表」这个选择，我们看清了三笔交易：用一张 Map 换极简与可窥探、代价是放弃封装；用不标准化键换精确匹配与 symbol 私有频道、代价是把一致性责任甩给调用方；用裸数组换透明语义、代价是高级能力得自己造。

这张表已经能跑了，但它现在还只是被关在一个函数里的一块内存。它凭什么能被公开成实例字段、凭什么能让两个发射器共享同一张表、那些方法又凭什么不需要 `this` 就能工作——这是下一章《函数工厂与无 this 的方法》要解开的扣。
