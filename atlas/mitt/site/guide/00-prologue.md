# 导读：mitt 源码解读

## 这本书在讲什么：一句话主线

你大概用过事件总线：一个模块喊一嗓子「数据好了」，另一个模块听见了去做事。市面上干这事的库很多，能力也很全——能设优先级、能「只触发一次」、能限制监听器数量、能异步派发。可 mitt 这个压缩后约 200 字节的小东西，偏偏把这一长串能力全砍了，最后整个库的状态只剩下**一张 `Map`**：键是事件名，值是这一类事件的处理函数排成的数组。

把整本书压成一句话，它讲的是：**一个事件发射器可以小到只剩一张表，而这张表不只是运行时的全部状态——连类型层的类型推导、通配符的 catch-all、乃至最后分发到各运行时的多格式外壳，全都从这一张表长出来。**

展开看，这条主线怎么落到每一层（layer）：

- 运行时的三件事——订阅、退订、派发——说到底全是读写这张表：订阅是写、退订是改、派发是读。前四章（primitive）把这张表从无到有搭起来，并让方法靠闭包绑定它、而不是靠 `this`。
- 往上的 composite 层，每一章都在用同一个路数反复答同一道题——**怎么复用这一张表、不另起第二套结构**：派发靠「进门先复制一份快照」来抵御处理器中途改表；通配符不是新结构，是表里的一个保留键 `'*'`；类型层也给这张表套上一层「键 → 值类型」的映射，让全 API 的类型自动派生。
- 到了 system 层，这份已经造好的函数一个字不改，只在外面套三套模块外壳，靠 `package.json` 的条件映射把每个运行时路由到对的那一份。

撑起这条主线的，是一条贯穿每一层的取舍逻辑：mitt 在每一层都用某个约定或技巧（闭包替 `this`、惰性建表、位运算抹平边界、快照、保留键、反向索引、条件类型），把「会撑大体积的分支、样板、封装、独立代码路径」一一抹掉，换来「零新增代码路径」和极致的体积；代价则是把封装性、可读性、去重和边界处理这些责任，系统性地让渡给调用方或读者。

## 怎么读这本书：两条阅读路线

### 路线一：从头读到尾（按依赖顺序）

不知道从哪开始？按下面这个顺序读最稳，每一章都是踩着前一章的地基往上盖：

1. **《把 pubsub 退化成一张查找表》**——立地基：发射器的全部状态就是一张 `Map`，三步操作全是读写它。
2. **《函数工厂与无 this 的方法》**——承接那张表，回答「方法凭什么不靠 `this` 就能摸到它」：靠工厂调用那一刻形成的闭包。
3. **《惰性初始化的追加式订阅》**——表和方法都有了，看第一个动作「写表」：第一个处理器到来才建数组，且从不查重。
4. **《无分支安全移除与重载清空》**——能写就要能删，看第二个动作「改表」：用一个位运算把「找不到」的边界抹平成一条无分支的直线。
5. **《快照式派发抵御中途改表》**——写、删都讲了，看第三个动作「读表」：进门先把名单复印一份，锁死本轮该叫醒谁。
6. **《通配符星号的第二条派发路径》**——派发已稳，给它加 catch-all：`'*'` 是表里的保留键，派发多走一趟。
7. **《一张 Events 映射派生全 API 类型》**——运行时讲完，镜头切到类型层：给那张表套一层「键→值类型」映射，全 API 类型自动派生。
8. **《条件类型区分「可不带数据」的事件》**——类型派生已立，再挖一个判分：用条件类型在编译期决定哪些事件能不带数据触发。
9. **《一源多格式通吃所有 JS 运行时》**——内核全部就位，最后看它怎么换三套外壳，把这一份函数递给所有运行时。

### 路线二：按你的目标抄近道

- **「我只想搞懂那张表运行时怎么增、删、派发」** → 读 1 → 3 → 4 → 5。这四章是运行时心脏，看完你就拥有了一个能跑的 emitter。
- **「我在意方法为什么能安全解构、`this` 怎么没了」** → 读 1 → 2。第一章给你那张表，第二章解释方法靠什么绑住它。
- **「我想看类型层怎么从一张映射派生出全部 API」** → 读 7 → 8（先扫一眼 1 知道那张表长什么样即可）。这两章是纯类型把戏，几乎不依赖运行时细节。
- **「我只想搞懂通配符 / catch-all」** → 读 5 → 6。先懂快照派发，再看保留键 `'*'` 怎么复用它。
- **「我想学『一个 npm 库怎么一源多格式通吃所有运行时』这份发布工程」** → 直接读 9。它几乎独立，前置只需知道「有个叫 `mitt()` 的函数工厂」。
- **「我想理解 mitt 凭什么这么小——它的极简哲学」** → 读 1 → 3 → 4 → 5。尤其第 4 章那个位运算抹平边界，是「为字节让步」最集中的体现。

## 贯穿全书的核心原理

读完各章你大概会有个感觉：好几个地方似曾相识。不是错觉——下面这几条，是会在好几章「换个化身再次现身」的底层机制。认出它们，各章就串起来了。

**1. 一张表，所有路径复用它。** 这是全书的总原理，整本书没有第二个状态容器。第 1 章《把 pubsub 退化成一张查找表》立起这张 `Map`；第 3 章《惰性初始化的追加式订阅》的 `on`、第 4 章《无分支安全移除与重载清空》的 `off` 都只是查表、写表；第 5 章《快照式派发抵御中途改表》的 `emit` 只是读表；第 6 章《通配符星号的第二条派发路径》的通配符不是新结构，而是这张表里的一个保留键；第 7 章《一张 Events 映射派生全 API 类型》在类型层给这张表套上一层映射；第 9 章《一源多格式通吃所有 JS 运行时》的整套分发，不改这张表一个字，只换外壳。认出这条，你就理解了 mitt 为什么能把体积压到极致——它从不为新增能力另造结构，只反复榨取同一张表。

**2. 把边界抹平成一条无分支的直线。** 这一手出现了好几次，每一次都是「让边界情况自己变成无害的空操作，省掉 `if`」：第 3 章拿 `get` 的返回值同时回答「在不在」和「给我数组」，省掉一次额外的 `has` 查询；第 4 章用 `indexOf(handler) >>> 0` 把「找不到」的 `-1` 改写成必然越界的下标、让 `splice` 自己扑空；同章还用「省略 handler」的重载替代一个独立的 `clear` 方法。它们是同一个手艺的不同化身，代价都是把可读性让渡给读者。

**3. 借用一个特殊的值，让现有机制零成本多长出一个能力。** mitt 极爱这一招：第 1 章用 `symbol` 当事件名，白捡一个「私有频道」（引用没泄露就没人能订阅）；第 6 章把 `'*'` 约定成通配符保留键，复用同一套增删派发就长出 catch-all；第 8 章《条件类型区分「可不带数据」的事件》借用 TypeScript「可选属性的索引访问天然含 `undefined`」这条既有约定，零额外配置就判定出哪些事件能不带数据触发。三处都是「不新增结构，只给某个特殊值赋予额外语义」。

**4. 对齐既有生态的语义，不自造一套。** mitt 多次主动贴齐大家已经熟悉的约定：第 3 章的「不去重」对齐 Node `EventEmitter` 的 `on`；第 5 章快照派发带来「移除延迟一拍生效」，也恰好与 Node `EventEmitter` 一致；第 8 章直接借 TS 既有约定当判分依据；第 9 章把 `types` 钉在 `exports` 首位，遵循的是 TS 官方约定。换来的是「使用者不用多记一套规则」。

**5. 类型安全是一种「边界属性」——越过 API 边界即退化为联合与断言。** 这是类型层两章（第 7、第 8）的共同骨架：第 7 章公开接口对外精确（每个事件名 ↔ 精确的数据类型），一进实现就把所有处理器揉成联合、靠 `as` 断言来回转换；第 8 章对外两条重载是严格契约，内部实现却对所有键把数据标成可选、用非空断言兜底。精确性只活在公开 API 那条边界上，内部一律宽松——这是给一张「运行时装着各种处理器」的异质表套上类型的唯一现实做法。
