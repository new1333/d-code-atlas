# 编译期宏的本质：运行时不存在的「变换提示」

> 本章属于基础层（primitive）。这是全书第 1 章，没有前置章节。
> 学完你能：用一句话讲清「Vue 的宏为什么是运行时根本不存在的伪函数，以及这个设计换来什么、付出什么代价」。

## 1. 为什么需要它

这本书要讲的是 Vue Macros，一个靠「编译期宏」吃饭的生态。但要把后面 13 章讲透，得先回答一个最底层的问题：到底什么是「编译期宏」？为什么 Vue 要发明这么个东西？这一章就是全书的地基，把这个概念立住，后面所有章节才有支点。

先看一个具体场景。你在写一个 Vue 组件，要声明它接收哪些 props。最朴素的写法是甩一个完整的选项对象，或者写一个 `setup(props, { emit })` 函数，再把模板用到的变量挨个 `return` 出去。能写，但样板冗长，类型也不友好。

真正让人别扭的不是「能不能写」，而是一个更隐蔽的事实：组件接收哪些 props、触发哪些事件、暴露哪些方法，这些信息在你写完代码那一刻就完全定死了，是静态的、编译期就能看清楚的。可旧语法偏要把这份早就确定的结构，推迟到运行时用对象字面量去反复表达，每次渲染都背着一份本可以省掉的开销。

你大概会想：这么确定的东西，为什么不能让编译器替我写？接下来的 13 章都在回答这个问题，而答案的起点就是本章要立的那个概念，编译期宏。

## 2. 核心思想

宏是写给编译器看的「变换提示」。它假装成一次普通的函数调用，其实只是给编译器递了个信号——在这个位置，把声明式代码原地改写成等价的运行时代码，然后把这个「假函数」从产物里彻底删掉。

这句话里藏着三个动作，后面会反复用到：**伪装成函数**、**编译期原地改写**、**运行时彻底擦除**。

## 3. 心智模型

把宏从你敲下键盘到最终跑起来，拆成六步：

1. 你在源码里写下一个「宏调用」，它有名字、有参数，长得和一个普通函数调用一模一样。
2. 但这个名字在运行时根本不存在：它没有被 `import`，也不指向任何真实函数。
3. 编译器在编译期把源码解析成一棵抽象语法树（AST），按「调用名 + 出现位置」认出哪些节点是宏调用。
4. 对每个认出来的宏调用，编译器拿一段**等价的、能独立跑的运行时代码**，把它原地顶替掉。
5. 顶替完，原来那个宏调用的痕迹从 AST 里彻底消失。
6. 最后交付到运行时的代码里，宏已经不在了，只剩下它被改写后的等价物，所以运行时没有任何额外开销。

这六步可以压缩成一个对照：

| | 源码侧 | 产物侧 |
|---|---|---|
| 宏调用 | 存在，伪装成函数调用 | **完全不存在** |
| 等价物 | 没有 | 只剩改写后的运行时代码 |

源码里有个「假函数」，产物里这个函数连同它的名字都蒸发了，只剩它换出来的真东西。

## 4. 关键权衡

这一节是全章的重头戏。宏之所以长成现在这个样子，是几组实实在在的取舍换来的，每一条都化解一个本质矛盾。

### 权衡一：伪装成函数，换来「零成本的自然感」，代价是「它根本不是函数」

第一个矛盾是：宏既要让调用处写得像普通函数一样自然，又要在编译期能被认出来，还要在运行时不留一点开销。

Vue 选的路是让宏伪装成一次普通函数调用，编译器静态认出后把它擦掉。这一招同时换来了三样东西：语法和普通函数一样自然，用户完全不用 `import`，运行时零开销（编译期就处理完了）。

代价也跟着来了：既然它不是真函数，就没有真实函数语义。你不能像对待普通函数那样灵活地用它。它既不能被赋给一个变量留到以后再调，也不能塞进条件分支或回调里，必须老老实实写在 `<script setup>` 的顶层。原因很直接，编译器做的是静态识别加改写，必须能在编译期一眼定位到它；一旦你把它藏进条件或回调，就等于要求运行时去求值，这和「宏只在编译期有意义」直接冲突。

这里化解的本质矛盾，其实是所有「编译期变换」共有的骨架：**想让一段语法在编译期就被处理掉，它就必须在编译期可被静态定位**。越灵活的写法（动态、条件、嵌套），越逃出编译器的视野。

### 权衡二：编译期就把结果定死，换来「产物干净」，代价是「普通工具链不认识它」

第二个矛盾在「编译期 vs 工具链生态」。宏选择在编译期就把要展开的东西完全确定、擦除并改写，于是运行时产物特别干净，性能可预测，组件结构在编译那一刻就定型了。

代价是：宏是一个不需要 `import` 的「全局幽灵函数」，普通 JS 工具链默认不认识它。ESLint 会冲你喊 `defineProps is not defined`，得靠配置 globals 或专门插件才能消停；纯 TypeScript 编译器也不认这些全局宏，Vue 自己的编译器又不做类型检查，你得另外靠 `vue-tsc` 或 Volar 语言服务才拿得到类型提示。

这背后还有一个特点：宏的类型不是一段真实的 TS 函数签名，而是语言服务靠虚拟代码模拟出来的（运行时产物和编辑器提示各走一条路，这是后面「双轨制」章的命题，这里只点一句）。

### 权衡三：运行时彻底消失，换来「零体积零调用栈」，代价是「调试全靠 sourcemap」

第三个矛盾在「产物精简 vs 可调试」。宏选择在运行时彻底消失，于是它不增加一丁点包体积，也不给调用栈多加一层。

代价是可调试性受损：你运行时打的断点、看到的调用堆栈、报错抛出的位置，全指向编译后的产物，而不是你手里写的源码。源码里那个宏调用早就没了，调试器找不到它。要想把产物里的位置还原回你写的源码，必须额外靠 sourcemap。

这三条权衡其实是同一个根本选择从三个角度看：**把工作从运行时搬到编译期，省下的是运行时的钱，付的是编译期和工具链的复杂度**。后面 13 章你会反复看到这个选择的不同侧面——识别宏要靠 AST、产物能回溯源码要靠 sourcemap、类型提示要靠虚拟代码，全是在为这个根本选择善后。

## 5. 最小原理演示

光说不练。下面用一个 30 行出头的玩具编译器，把「伪函数被识别 → 原地改写 → 运行时擦除」这一件事演透。我们造一个叫 `defineConstant` 的玩具宏：写 `defineConstant('MSG', 'hello')`，编译器原地把它换成 `const MSG = 'hello'`，然后 `defineConstant` 这个名字从产物里彻底消失。

```js
import { parse } from '@babel/parser'
import _traverse from '@babel/traverse'
import _generate from '@babel/generator'
const traverse = _traverse.default   // ESM/CommonJS 互操作兜底，教学忽略
const generate = _generate.default

// 宏清单：宏名 →「拿到参数，吐出一个等价的 AST 节点」
const MACROS = {
  defineConstant(args) {
    return {
      type: 'VariableDeclaration',
      kind: 'const',
      declarations: [{
        type: 'VariableDeclarator',
        // 第 1 个参数是字符串字面量 'MSG'，取出它的值造一个同名标识符 MSG
        id: { type: 'Identifier', name: args[0].value },
        init: args[1],   // 第 2 个参数 'hello' 字面量原样用作初值
      }],
    }
  },
}

// 极简编译器：解析 → 按 callee 名识别宏 → 原地替换 → 产出干净代码
function compile(src) {
  const ast = parse(src)
  traverse(ast, {
    CallExpression(path) {
      const { callee, arguments: args } = path.node
      // 原理点①②：宏伪装成函数调用，编译器靠「调用名」静态识别它
      if (callee.type === 'Identifier' && MACROS[callee.name]) {
        // 原理点③：用等价的运行时代码，把这个调用节点原地顶替掉
        path.replaceWith(MACROS[callee.name](args))
      }
    },
  })
  // 原理点④：generate 之后，产物里再也搜不到 defineConstant 这个名字
  return generate(ast).code
}
```

跑一下看效果：

```js
const src = `
defineConstant('MSG', 'hello')
defineConstant('COUNT', 42)
`

console.log(compile(src))
// 产物：
// const MSG = 'hello';
// const COUNT = 42;
```

产物里你翻烂了也找不到 `defineConstant` 这几个字母。源码里那个「函数」连同它的名字，被编译期替换彻底抹掉了，运行时只剩它换出来的真实声明。这就是宏干的事。

注意代码里标出的四个原理点，正好对上前面的心智模型：`CallExpression` 就是「伪装成函数」，`MACROS[callee.name]` 查表就是「编译期识别」，`path.replaceWith` 就是「原地改写」，`generate` 出来的代码里宏名消失就是「运行时擦除」。

## 6. 执行轨迹

拿刚才那段输入，一步一步走一遍编译器眼里发生了什么：

1. **输入**：源码里有两个伪装成函数调用的宏，`defineConstant('MSG', 'hello')` 和 `defineConstant('COUNT', 42)`。
2. **解析**：`parse(src)` 把源码变成一棵 AST。这两个宏调用在树里都是 `CallExpression` 节点，`callee.name` 都是 `'defineConstant'`，各自带着两个参数子节点。
3. **识别**：`traverse` 遍历到每个 `CallExpression`，拿 `callee.name` 去宏清单 `MACROS` 里查，命中，确认这是宏，不是普通函数。
4. **改写**：对每个命中的节点，调 `MACROS.defineConstant(args)`，吐出一个等价的 `VariableDeclaration` 节点，`path.replaceWith` 把原调用节点原地顶替。这时 AST 里那两个 `CallExpression` 已经被两个 `const` 声明取代。
5. **产出**：`generate(ast)` 把改写后的 AST 重新拼成代码，得到 `const MSG = 'hello'` 和 `const COUNT = 42`。

走完这五步，源码里的宏函数名在产物里已不存在，运行时拿到的是干净的真实声明，没有任何额外调用开销。

真实 Vue 里的 `defineModel` 是同样的道理，只是换出来的等价物更丰富：源码一行宏调用，编译后展开成一个 `modelValue` prop、一个 `update:modelValue` 事件，外加一个 ref，而 `defineModel` 这个名字同样从产物里消失。

## 7. 教学简化说明

为了把「伪函数被擦除」这一件事讲透，本章演示故意砍掉了很多东西：完整的单文件组件（SFC）解析、AST 识别的健壮性论证（为什么必须用 AST 而不是正则）、sourcemap 怎么生成、多个宏同时改写一个节点时谁先谁后、每个 Vue 内置宏具体的去糖细节，还有类型那一整摊事。这些全部留给后面的章节。

## 8. 小结

回到开头那个问题：为什么这么确定的东西不能让编译器替我写？答案是，可以，而且 Vue 就是用「编译期宏」做到的。一句话收束：**宏是写给编译器的变换提示，它伪装成函数、在编译期被静态识别并原地改写成等价运行时代码、然后从产物里彻底消失，换来零运行时开销和声明式语法，代价是它没有真实函数语义、不被普通工具链认识、调试还得靠 sourcemap。**

但这一章只回答了「宏是什么」，还没回答「具体用宏去糖了什么」。Vue 到底把哪些声明式写法喂给了这套擦除机制？这正是下一章「`<script setup>` 与内置宏的设计动机」要接着讲的事。
