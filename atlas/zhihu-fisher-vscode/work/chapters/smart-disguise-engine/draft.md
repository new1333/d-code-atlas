# 第 10 章 智能伪装引擎：把知乎标签页变成「正在编辑的代码文件」

你在工位上用 VSCode 刷知乎，最怕的不是被知乎封号，而是被路过的同事或老板瞄到——「咦，你那个标签页怎么是个知乎文章？」原生扩展只要把知乎内容塞进 webview，标签页的标题和图标就是赤裸裸的中文，一秒露馅。

真正想要的效果是这样的：**只要我视线一离开这个标签页（切走、切到别的窗口），它就得在那一瞬间变成一个「正在被编辑的代码文件」**——标签上的名字像代码文件名、图标像代码文件图标、内容像一屏带高亮的代码；等我切回来，它又秒变回知乎。而且变得要「稳」，不能每次切走都换个新名字闪来闪去，那样反而更招眼。

这一章就拆这个「瞬间变脸」的机制。它只依赖第 1 章那个全局 Store（拼图标路径时只读借用一下里面的扩展根地址），自身不参与可变状态通信，所以全局单例那一套这里不再重复。

## 一、要伪装的两样东西，得用两套不同的更新策略

失焦的瞬间，其实有**两层东西**要同时伪装：

- **身份层**：标签页的标题和图标。这是 OS 层面能看到的东西，路人扫一眼就看这里。
- **内容层**：webview 里面盖着的那一层假代码。只有当人主动点进来、凑近看时才暴露。

这两层对「变不变」的要求是拧着的，说人话就是——身份要**稳**，内容要**活**。

打个比方：想象一个在工位上摸鱼的特工。他的**工牌**（姓名牌、头像）一旦挂上去就别再换，换来的是同事路过时心里嘀咕「哦还是那个张三」，不会因为工牌天天变引起注意；但他面前那块**黑板**上的「工作内容」，得隔一会儿就擦掉重写几句，不然别人瞟第二眼就发现这黑板一上午一个字没动。

这就是全章的灵魂，一句话点透：**身份（文件名/图标）一次性确定并冻结，内容（假代码）每次重画**。标签条上永远稳定不闪，叠层里却看着像一直在被编辑。下面两节分别看这两层各自怎么实现，第五节用一个能跑的脚本把两层一起演出来。

## 二、身份层：三组词池 + 一张缓存表，拼完就锁死

身份层要做的事很简单：给一个知乎页面，编出一个看着合理的「假文件名 + 假图标」，并且编完就不再变。

文件名怎么编才像真的？答案是**三组正交的词池各随机取一个拼起来**：

- 前缀池：`app-`、`core-`、`util-`、`lib_` ……
- 名字池：`utils`、`service`、`handler`、`config` ……
- 扩展名池：`.ts`、`.py`、`.rs` ……

三池一拼，`app-` + `utils` + `.ts` = `app-utils.ts`，一眼看过去就是个正经的 TypeScript 文件。图标呢？扩展名对应到一种语言，语言再对应到扩展打包资源目录里的一个内置 svg 图标（比如 `.ts` 指向 TypeScript 的文件图标）。拼图标路径时用到的「扩展根地址」，就是第 1 章那个全局 Store 在激活时注入的 `extensionUri`，这里只读借一下、不持有。

**关键在缓存**。每个 webview 有一个唯一标识，第一次失焦时随机拼出一个身份，**写进一张以标识为键的缓存表**；之后再失焦，直接查表、原样返回，不再随机。这就是身份层「稳」的来源——同一个页面从头到尾顶着同一个假名字，OS 层不会反复重绘标签，路人看着永远是一样的。

当然，缓存也意味着身份被锁死。所以导航到一篇新文章、或 webview 被重建时，宿主得主动调一下「清这个标识的缓存」来换新身份。换句话说，身份不是永不改变，而是「换的时候显式换，平时坚决不动」。

## 三、内容层：骨架按调用次数轮转，token 每次重随

身份解决了，剩下内容层：要铺一层假代码上去，而且每次失焦都得「重画」，看着像还在被持续编辑。

最直觉的做法是每一行都纯随机——但这会翻车。纯随机会冒出五个连续的右大括号、或者 `import` 接 `import` 接 `import` 的鬼畜序列，远看就不像程序。所以这里做了一个聪明的拆分：**把一行代码拆成「骨架」和「token」两部分，给它们两套不同的更新策略。**

- **骨架**（这一行是 `const x = y;` 还是 `function f() {}` 还是 `interface IX {}`）：按「该语言被调用的总次数」取模**轮转**着选。换句话说，语言表里每种语言都有一串写好的模板，按 `0, 1, 2, …, N-1, 0, 1, 2 …` 这样轮着取。
- **token**（骨架里那些变量名、值、字符串）：每次都**重新随机**。

这个轮转用的是一个模块级、跨所有 webview 共享的索引。骨架是确定性的（同一语言第二次渲染会和第一次结构重合），但因为 token 每次都重随、而且这层代码只在主动凑近看时才显现，这点重合几乎没人察觉——换来的是骨架天然按 `导入→类型→函数→语句` 的真实程序顺序循环，看着就是一份正常代码。

还有一招省事的设计：**着色不接真高亮引擎**。每个模板直接吐出 VSCode 自己用的着色 CSS 类名（`mtk1`～`mtk21`，关键字一类、变量一类、字符串一类各占一个类名），webview 只要自带一张「类名→颜色」的映射表就能上色，像素级还原编辑器观感，还零运行时依赖。代价下面权衡里再说。

## 四、两层各取所需：失焦换身份+重画代码，获焦还原真身

两层机制都有了，剩下把它们挂到「失焦/获焦」这两个事件上。整个触发时序是这样的：

```
失焦（面板切走、inactive）
  → 取伪装身份：查缓存，命中直接复用；否则三池随机拼一个并冻结
  → 把 标签标题 / 标签图标 改成这个身份（OS 层可见）
  → [若「代码叠层」开关已开] 用同一个缓存身份反查语言
      → 生成 100 行假代码 → 注入 webview（默认隐藏）→ 发 showDisguise 消息让前端亮出来

获焦（面板切回、active）
  → 从全局映射里取这篇知乎的真标题 / 真图标，写回标签
  → 发 hideDisguise 消息，让前端把那层假代码藏起来
```

这里有两个值得注意的细节。

**第一，代码叠层复用的是同一个缓存身份。** 内容层并不重新随机一种语言，而是拿着已经冻结的文件名，从扩展名反查出语言（`app-utils.ts` → `.ts` → TypeScript），再去取对应骨架。这就保证了「标题是 ts、内容也是 ts」，不会出现 ts 文件名配一段 Python 代码的穿帮。

**第二，两层用的是不同的触发条件，而且默认值还不一致。** 身份层在失焦时几乎无条件生效（走的是默认「开」的判断），代码叠层却要等用户显式打开「代码叠层」开关（默认「关」）。这会带来一个中间态：标签页已经伪装成了 `app-utils.ts`，但你真点进去、内容还是知乎——因为叠层开关没开。这个细节是日后排查时最容易踩的坑，第四节权衡里展开。

## 五、最小演示：连失焦三次，标题纹丝不动、代码却在变

光说不练不踏实。下面这段脚本是机制骨架（不是真源码，真源要挂在 VSCode 宿主里跑不了），用 `node` 或 `bun` 直接就能跑。它用一个普通对象模拟「面板」（带 `title`/`icon`，外加一个会收消息的假 webview），手动调 `onBlur`/`onFocus` 模拟失焦/获焦。为了好读，语言只留 ts、py 两种，假代码只画 5 行。

```ts
// 智能伪装引擎 · 原理骨架（可 node/bun 直接跑）
// 用普通对象模拟「面板」：带标题、图标，外加一个会收消息的假 webview

// 1) 语言表：每种语言 = 三组词池 + 一组骨架模板
const LANGS = {
  ts: {
    icon: 'typescript.svg',
    prefixes: ['app-', 'core-', 'util-'],
    names: ['utils', 'service', 'handler'],
    exts: ['.ts'],
    // 骨架：结构固定，只留「空」给 token 填
    patterns: [
      (t) => `const ${t.var} = ${t.val};`,
      (t) => `function ${t.fn}(${t.var}) { return ${t.var}; }`,
      (t) => `interface I${t.cls} { id: number; ${t.var}: string; }`,
    ],
  },
  py: {
    icon: 'python.svg',
    prefixes: ['lib_', 'mod_', 'app_'],
    names: ['config', 'parser', 'worker'],
    exts: ['.py'],
    patterns: [
      (t) => `${t.var} = ${t.val}`,
      (t) => `def ${t.fn}(${t.var}):\n    return ${t.var}`,
      (t) => `class ${t.cls}:\n    pass`,
    ],
  },
};

// 2) 两层状态的「家」：身份缓存 + 模块级轮转索引
const idCache = new Map();    // webviewId -> { title, icon, lang }
const rotation = new Map();   // lang -> 下一个骨架下标

const pick = (arr) => arr[Math.floor(Math.random() * arr.length)];

// 内容层：骨架按调用次数取模轮转，token 每次重随
function nextSkeleton(lang) {
  const pats = LANGS[lang].patterns;
  const i = (rotation.get(lang) ?? 0) % pats.length;   // 取当前骨架
  rotation.set(lang, (rotation.get(lang) ?? 0) + 1);   // 推进一格
  const t = {
    var: pick(['data', 'count', 'name']),
    val: pick(['42', '"ok"', 'true']),
    fn: pick(['getData', 'parse']),
    cls: pick(['User', 'Node']),
  };
  return pats[i](t);   // 骨架固定、token 每次重随
}

// 身份层：命中即原样返回（冻结），否则拼一个并缓存
function getDisguise(id) {
  if (idCache.has(id)) return idCache.get(id);
  const lang = pick(Object.keys(LANGS));
  const L = LANGS[lang];
  const identity = { title: `${pick(L.prefixes)}${pick(L.names)}${pick(L.exts)}`, icon: L.icon, lang };
  idCache.set(id, identity);     // 冻结身份
  return identity;
}

// 模拟面板 + 失焦/获焦
function makePanel(id) {
  return { id, title: '知乎·如何看待…', icon: 'zhihu.svg' };
}
function onBlur(panel) {                 // 切走：换身份（命中则不变）+ 重画代码
  const d = getDisguise(panel.id);
  panel.title = d.title;                 // ← 命中时三次完全相同，不闪
  panel.icon = d.icon;
  const code = Array.from({ length: 5 }, () => nextSkeleton(d.lang)); // ← 每次重画
  console.log(`[失焦] 标题=${panel.title}`);
  console.log(`       代码：\n         ${code.join('\n         ')}`);
}
function onFocus(panel) {                // 切回：还原真身
  panel.title = '知乎·如何看待…';
  panel.icon = 'zhihu.svg';
}

// 跑：同一个 id 连续失焦 3 次
const p = makePanel('wv-1');
onBlur(p);
onBlur(p);
onBlur(p);
```

跑起来你会看到类似这样的输出（token 是随机的，你跑出来的变量名会不一样，但**关键规律一模一样**）：

```
[失焦] 标题=app-utils.ts
       代码：
         const count = "ok";
         function getData(name) { return name; }
         interface IUser { id: number; data: string; }
         const name = true;            ← 骨架回到第 1 个（取模轮转一圈）
         function parse(count) { return count; }
[失焦] 标题=app-utils.ts            ← 注意：第二次，标题纹丝不动（缓存命中）
       代码：
         interface INode { id: number; name: string; }   ← 骨架从上一轮的下一格接着转
         const data = 42;             ← 但 token（变量名、值）全换了
         ...
[失焦] 标题=app-utils.ts            ← 第三次，标题还是它
       代码：
         ...骨架继续往前转，token 又重随一遍...
```

盯着这两行差异看：**标签标题三次完全相同，代码却每次都在变。** 这一行行为差异，就是整章的灵魂——身份冻结（靠缓存），内容重画（靠轮转+重随）。两次失焦之间，标签条上没有任何闪烁，叠层里却像有个程序员一直在敲键盘。

## 六、关键权衡

这一章机制密集，四条权衡各自对应一个独立的设计决策。

**权衡 1：身份缓存 ↔ 内容重生成。** 做了「标签页身份按页面缓存、命中即原样复用」的选择，换来标签条上标题/图标稳定不闪——路人扫一眼永远是「那个文件」，不会因为每次失焦换名字反而招眼；代价是同一个页面永远顶着同一个假文件名（不够「随机」），而且导航到新文章时必须记得主动清缓存、换新身份，否则新页面还顶着旧名字。

**权衡 2：全局轮转骨架 ↔ 仅 token 随机。** 做了「代码骨架按调用次数取模轮转、而非每行纯随机」的选择，换来结构可信——骨架天然按 `导入→类型→函数→语句` 循环，不会冒出连续右大括号或 `import` 接 `import` 的鬼畜序列，远看就是一份正常程序；代价是骨架其实是确定性的、两次渲染结构会重合，且轮转索引全局共享，多页面同时伪装时各自的骨架序列会互相穿插——好在这层代码只在主动凑近看时才显现、token 每次又重随，这两点都不致命。

**权衡 3：预烤着色 span ↔ 手写海量模板。** 做了「不接真实语法高亮引擎、直接吐编辑器自带的着色 CSS 类名」的选择，换来像素级还原真实编辑器观感、且 webview 零运行时依赖（只需自带「类名→颜色」映射）；代价是每种语言都得手写一组模板闭包，整个生成器是上千行近乎重复的代码，而且生成的「代码」细看并不构成一个能跑的程序，只是形似。

**权衡 4：两层独立触发 ↔ 半伪装中间态。** 做了「标题/图标层失焦时近乎无条件生效（默认开）、代码叠层按开关显式触发（默认关）」的选择，换来标题层零延迟、永远生效的「轻量伪装」性价比，叠层留给愿意配置的人按需开启；代价是两层用着不同的开关、不同的默认值，会出现「标题已伪装成 `app-utils.ts`、点进去内容还是知乎」的半伪装中间态，而且同一个 `enableDisguise` 在不同读取点的默认值还不一致（一处默认开、多处默认关），是日后排查时最容易踩的认知坑。

## 七、小结

这一章的核心其实就一句话：**把「伪装」拆成身份和内容两层，给它们两套相反的更新策略——身份靠缓存冻结求稳，内容靠轮转+重随求活。** 三组词池拼出一个假文件名、一张缓存表让它不再闪；一套按调用次数取模的骨架索引保证代码结构可信、每次重随的 token 保证它看着新鲜；失焦时两层一起上、获焦时一起还原，代码叠层还复用同一个缓存身份来保证「标题和内容是同一种语言」。

这套伪装引擎本质上是个不依赖运行时的纯工具类——它只读借了全局 Store 里的扩展根地址，自身那张缓存表并没有进 Store。下一章《扫码登录全流程》会换到扩展的另一面：登录这一步同样绕不开宿主环境，它用的是一台真实浏览器去渲染登录页、截图二维码，从而绕过登录加密。
