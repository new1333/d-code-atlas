这本书在讲什么：一句话主线 ​

zhihu-fisher-vscode 是一个让你在 VSCode 里偷偷刷知乎的摸鱼扩展。但当你剥开它的功能清单——侧边栏热榜、详情页阅读、评论翻页、收藏夹、扫码登录、伪装成代码文件——往下看一层，会发现它其实在反复用两件原语对抗两重外部约束。

约束是这两重：VSCode 平台只给你一个回合制的侧边栏契约和一个沙箱化的 WebView（你不能往里 push 数据，只能等它来问；你不能在 WebView 里跑前端框架，只能整页重画或发消息）；知乎的反爬和登录加密你又逆向不动（签名算法一天变三次，硬刚是亏本买卖）。

在这种约束下，扩展反复用的两件原语是：

  1. 一个模块级可变单例容器——所有模块 import 同一个对象，把扩展全生命周期的资源（上下文、面板映射、那台 Chrome、Cookie）全挂上去，换来零胶水跨模块通信。
  2. 一台伪装好的真实 Chrome 替我们去跑知乎自己的加密 JS——读内容靠它在页面上下文里抠数据；登录扫码靠它渲染知乎自己的登录页、让前端 JS 自己算签名 Cookie。这个扩展从头到尾没逆向过任何知乎加密，它的策略是「让知乎自己算，我把结果偷过来」。

全书十三章，都是这两件原语在不同业务面的具象化：读内容、写操作（写操作反而退回纯 HTTP，因为不必渲染）、侧边栏列表、详情爬取、详情渲染、评论/收藏分页、伪装换皮、扫码登录、最后是装配。理解了这两件原语和它们为什么这样选，全书就贯通了。

怎么读这本书：两条阅读路线 ​

一、线性路线（按拓扑序） ​

按拓扑顺序读，每一章承接前一章打开的新问题：

  1. 全局共享状态容器——立地基：所有模块以后都往这块「公共留言板」上挂字段。
  2. Cookie 凭证的清洗与校验——把 Cookie 从静态凭证重新定义成「会脏、会缺、会失效」的活动状态，入口处摆三道关。
  3. 防反爬浏览器引擎——开一台真实 Chrome 当全扩展共享的公车，做三件伪装（伪造 UA、注入 Cookie、抹掉 webdriver），把「对抗」降级成「伪装」。
  4. 知乎 JSON API 写操作客户端——投票/收藏这些写动作反而退回纯 HTTP：伪装一整套浏览器请求头复刻知乎前端自己发的那条 XHR。
  5. 侧边栏内容列表——把 getChildren 写成状态机，按状态优先级返回占位/动作节点；列表用最轻 HTTP，却必须先过最重的浏览器闸门。
  6. 详情页爬取与反爬内容提取——同一台 Chrome 钻进页面上下文抠数据，配上一致性护栏（去重 + 批次上限 + 到底探测 / 关旧面板 + 关键词校验）。
  7. 详情页 HTML 渲染与双向消息——结构性大改动整页重画，运行时小更新走点对点增量消息，保住长文阅读的连续性。
  8. 评论父子树的游标分页——游标续传 + 累积全集 + id 去重 + 存全集显示当前页切片；三种续法四种存储策略，因为知乎评论接口各年代都有、靠谱度不一。
  9. 收藏夹树形结构与本地缓存——三级树懒加载、两种分页协议并存、三道闸互相兜底判停、选单专用缓存与树刷新分离。
  10. 智能伪装引擎——身份层（标题/图标）按 webview 缓存命中即冻结、内容层（假代码）每次重画；预烤 VSCode 自带的 mtk 着色 span。
  11. 扫码登录全流程——借力总纲：让知乎 JS 替我们算登录加密；隔离上下文 + 截图像素（绕污染 canvas）+ 轮询 URL（对加密免疫）+ 再导航一次让 JS 写签名 Cookie。
  12. 侧边栏伪装成假文件树——声明式 when + setContext 翻转一个布尔变量，让编辑器自己整组原子替换真列表与假文件树。
  13. 扩展激活与命令编排——activate 是唯一装配点；命令组只回吐 Disposable[] 由总注册函数摊平统一登记；deactivate 只清残羹冷炙。

二、按主题路线 ​

按你想搞懂的目标，挑一条子序列读：

  • 只想搞懂「反爬对抗」：2（Cookie 清洗）→ 3（防反爬浏览器）→ 6（页面上下文提数据）→ 11（登录也借浏览器算加密）。这条线把「让真浏览器替我们跑知乎自己的 JS」这个全书最反复出现的策略看完。
  • 只想搞懂「VSCode 平台契约怎么用」：5（TreeDataProvider 状态机）→ 7（WebView 双向消息 + 整页/增量分工）→ 12（声明式可见性）→ 13（组合根装配）。这条线集中讲「在 VSCode 的回合制契约里怎么把界面做出来」。
  • 只想搞懂「分页与缓存」：8（评论游标 + 累积全集）→ 9（收藏夹三道闸 + 选单缓存）。两章对照看：同样是「数据会爆量、又不能一次拉完」，评论和收藏夹因为接口可靠度不同，长出了几乎相反的存储策略。
  • 只想搞懂「伪装」（摸鱼灵魂）：10（智能伪装引擎：身份冻结 + 内容重画）→ 12（侧边栏整组替换）。前者治一点（标签页），后者治一片（侧边栏）。
  • 只想搞懂「读 vs 写」的轻重分工：3（读必须开重浏览器）+ 4（写退回轻 HTTP）→ 5、6 看读和写在侧边栏、详情里如何配合。这是全书最具反差的工程取舍。
  • 只想搞懂「装配与生命周期」：1（容器）→ 13（装配）。前者立容器、后者用容器把所有零件胶合起来。

贯穿全书的核心原理 ​

下面这些原理，都在多章以不同化身反复现身。认出它们，理解就贯通了。

1. 全局共享可变单例 + 异步防御性判空 + 集中收尾 ​

本质：所有模块 import 同一个对象当公共留言板，谁需要谁读写；因为是全局可变，异步流程中读到的值下一行 await 完可能就没了，所以消费者必须「取到立刻判空、await 后再判一次」；停用时集中一个收尾函数串行清理。

在哪几章现身：

  • 第 1 章立地基（讲透原理）。
  • 第 3 章把 browserInstance 挂上去、第 7 章把文章对象挂上去、第 10 章只读 extensionUri。
  • 第 13 章在 activate 里给 Store.context 赋值（全仓库唯一赋值点），在 deactivate 里置 null。

2. 借力而非逆向 / 让真浏览器替我们跑知乎自己的加密 JS ​

本质：知乎的反爬指纹和登录加密你都逆向不动，但知乎自己的前端 JS 一定能算出正确结果。所以把一台伪装好的真 Chrome 当「替我们算加密的算力」，扩展只管渲染、截图、等跳转、收割。

在哪几章现身：

  • 第 3 章反爬伪装（不开纯 HTTP 拼 header，开真 Chrome 整体通过安检）。
  • 第 6 章在页面上下文里 evaluate 把 JS 渲染后的 DOM 抠成数据。
  • 第 11 章扫码登录让知乎 JS 自己画二维码、自己写签名 Cookie（登录后再导航一次到 zhihu.com/hot 就是为了让 JS 把 __zse_ck 写进去）。

3. 按集合去重 + 增量合并 + 全集与当前视图分离 ​

本质：动态加载的数据，每拉回一批就用 Set 按 id 去重、只吸收新条目合并进持久全集；但渲染时永远只切「当前页那一片」，全集不直接显示。这个组合让「跨多次请求攒住状态」和「只展示用户当前关心的那片」同时成立。

在哪几章现身：

  • 第 6 章详情页：按回答 id 去重，每批上限 10 条 + 递归滚动。
  • 第 7 章相关问题：滚动后重复解析、按问题 URL 末尾 id 去重、有新增才发消息。
  • 第 8 章评论：累积列表从第 1 页一路攒到末页 + id 去重；显示时从全集切当前页那一片。

4. 用本地一致性护栏兜底不可靠的接口/动态页面 ​

本质：外部接口和动态页面不可信（总数会漂移、顺序与页码对不上、面板会残留旧结果、缓存会回旧答案），所以本地多叠几道互相兜底的判定，宁可写多遍也不能任何一遍漏掉。

在哪几章现身：

  • 第 6 章：详情页「批次上限 + 到底探测（滚动前后高度不变即止）」；AI 直答「先关旧面板 + 关键词校验拒绝旧缓存 + 临时源页重试」。
  • 第 8 章：评论「游标续传不偏移 + 累积全集 + id 去重」，因为问题评论接口的游标压根不可靠，只能本地全集兜底。
  • 第 9 章：收藏夹「三道闸判停」（有总数比总数 / 启发式不满一页 / 加载前后数量没变强制停）+ 第一道闸就地修正漂移的总数。

5. 状态驱动 + 事件触发重算（声明式可见性） ​

本质：不命令式地 show/hide 每个东西，而是把「在什么状态下显示什么」写成一台状态机或一组 when 条件，状态变了就 fire() 一下让平台重新来问，平台自己根据条件求值。

在哪几章现身：

  • 第 5 章侧边栏：getChildren 是按状态优先级分支的状态机（路径无效 → 浏览器没配 → 没登录 → 加载中 → 有数据 → 失败），改完共享状态 fire() 一下平台就来重新问。
  • 第 9 章收藏夹：getChildren 按 contextValue 分派三级树，懒加载藏在「返回即触发」里。
  • 第 12 章侧边栏伪装：写两行互斥的 when 条件绑同一个布尔变量，运行时只 setContext 翻一下变量，编辑器自己整组原子替换。

6. 身份/骨架稳定 vs 内容/状态每次重画 ​

本质：把更新策略一分为二——「所有人都瞄得到的表层」要稳（缓存命中即冻结），「只有凑近才看得清的里层」每次重画保鲜。两层各自独立触发，靠一个共享 key 保证一致。

在哪几章现身：

  • 第 7 章：结构性变化整页重画（DOM 骨架重建），运行时小更新走增量消息只改局部节点——保住滚动位置和输入态。
  • 第 10 章：身份层（标题/图标）按 webview 缓存命中即冻结不闪任务栏，内容层（假代码）每次失焦重画看着像还在被编辑；内容层从身份层缓存反查扩展名，保证「标题是 ts、内容也是 ts」。

7. 集中装配 + 命令组只回吐 Disposable ​

本质：开机时在一个入口里把所有对象装配好、用普通参数注入下去，每个子系统只回吐「可销毁句柄」由入口统一登记进宿主；关机时宿主遍历清单逐个 dispose，扩展只清宿主管不到的外部进程和容器内可变状态。

在哪几章现身：

  • 第 1 章容器：集中一个收尾函数串行清理全部资源，每段独立 try/catch。
  • 第 13 章装配：activate 是唯一装配点（组合根）；13 个 registerX 命令组签名形态各异（零依赖 / 收一个 / 收五个 / 收服务加五个），把运行时数据依赖直接写在签名里；registerAllCommands 用展开运算符摊平所有句柄统一登记。

下面这张表按 layer 列出全部 13 章，箭头表示 dependsOn（箭头指向被依赖的章）。读图要点：四层 primitive 是地基（互相少量依赖）；六层 composite 都建在 primitive 之上、彼此递进；三层 system 是把前面的零件胶合成完整扩展。

────────────────────────────────────────────────────────────────

  2  Cookie 凭证的清洗与校验         （无）
  3  防反爬浏览器引擎                → 1, 2
  4  知乎 JSON API 写操作客户端      → 2

composite（业务机制，建在 primitive 上）
  5  侧边栏内容列表                  → 1, 2, 3
  6  详情页爬取与反爬内容提取        → 1, 2, 3
  7  详情页 HTML 渲染与双向消息      → 1, 6
  8  评论父子树的游标分页            → 7
  9  收藏夹树形结构与本地缓存        → 4, 5
  10 智能伪装引擎                    → 1

system（系统级胶合，把零件组装成完整扩展）
  11 扫码登录全流程                  → 2, 3, 5
  12 侧边栏伪装成假文件树            → 5, 10
  13 扩展激活与命令编排              → 5, 7, 9, 11, 12

读这张图的两个要诀：

  • 从下往上读 = 「盖楼顺序」：先有容器和 Cookie 清洗这两块无依赖的纯本地原语，再立浏览器和 API 客户端这两个 outward-facing 引擎，然后才能建侧边栏和详情爬取，再上一层才能讲渲染和分页，最后是系统级胶合。这恰好是 topoOrder。
  • 横向看 layer = 「机制相似度」：所有 composite 章都在解决「数据从外部世界进来之后怎么管」——侧边栏是列表、详情是页面、评论/收藏是分页、伪装是身份。它们各自的取舍各不相同，但都复用同一组 primitive（容器、Cookie、浏览器）。

读到这里，你应该已经能在脑子里画出这本书的全景：四块地基 + 六块业务机制 + 三块系统胶合，全部依赖关系都收口到第 13 章的 activate 这一个装配点。从任何一章切入，顺着 dependsOn 反向追溯，你都能回到第 1 章那块公共留言板和第 3 章那台替你算加密的真 Chrome——这两件东西，就是全书的脊柱。
