# 实现计划 · Code Atlas 引擎（先行弹+ 渐进铺开）

**起点状态**：全空仓库——只有 `docs/`（requirements/design/6 ADR）、`CONTEXT.md`、`README.md`、`TMP_PROMPT.md`。无 `src/`、无 `package.json`、非 git 仓库。**全部代码从零写。**

**技术栈**：Bun 1.3+ 运行时 + TypeScript 引擎；Agent = `claude -p` headless 子进程（ADR-0001）；所有状态落 `manifest.json`（ADR-0002）；Source 对 Agent 强制只读（ADR-0005）。

**已确认的 `claude -p` 接口**（查官方 docs）：`-p "<prompt>"`、`--allowedTools`（可重复或逗号/空格分隔）、`--output-format text|json|stream-json`、`--system-prompt` 替换、`--add-dir` 加目录、`--model` 选模型、`--max-turns`。**无通用 `--timeout` 与 `--cwd` flag** → 工作目录由子进程 `cwd` 传；超时由 Orchestrator 自己在 spawn 层包一层。本地源目录用 `--add-dir` 让只读 agent 访问。

4. **目录骨架**：`src/{bin,stages,agents,prompts,lib}/`。

## Phase 1 · 基础库 `src/lib/`（先行弹的地基）

按依赖顺序逐个建，每个配最小自检：

- **`io.ts`** — 路径约定（`atlasRoot`、`runDir(key)`、`workDir`、`sourceDir`、`artifactPaths`）、`readJson/writeJson`（原子写：写 `.tmp` 再 rename）、`runKey(repoInput)`（URL 取 repo 段 / 本地取 basename，slug 转义）、`ensureDir`。
- **`topo.ts`** — `topoSort(chapters)`：Kahn 算法 + 环检测，返回 `{order, hasCycle, cycleNodes}`。纯函数，最先写 + 单测。
- **`pool.ts`** — `mapPool<T,R>(items, concurrency, fn)`：有界并发池，默认 4，错误冒泡。
- **`run-claude.ts`** — **核心集成层**。封装 `claude -p` 子进程：
  - 入参 `{ role, userPrompt, cwd, readOnly, addDirs?, model?, maxTurns?, outputFormat? }`。
  - `readOnly=true` → 硬编码 `--allowedTools Read,Glob,Grep`（ADR-0005，无逃生口）；`readOnly=false`（Writer/Assembler）→ 加 `Write,Edit`。
  - `cwd` 经 spawn `cwd` 传（不用 flag）；`addDirs` → 多个 `--add-dir`。
  - `--system-prompt` 注入 `prompts/{role}.md` 全文。
  - `--output-format json` 解析最终结果 + 流式 stderr 日志。
  - **超时**：Orchestrator 传 `timeoutMs`，到点 `SIGTERM`→`SIGKILL`。
  - 返回 `{ exitCode, durationMs, cmd(完整命令字符串,记入 manifest), stdout, stderr, resultText }`。
- **`manifest.ts`** — manifest 状态机（ADR-0002）：
  - 类型 `Manifest`（stages + chapters + version + source）。
  - `load/save`（CAS：写产物完整落盘后才 `setStatus done`）。
  - `nextPendingStage`、`stageStatus`、`markRunning/done/failed`、章节级同名方法。
  - `resetStage(--force 用)`。

**Phase 1 验收**：`bun test` 过 `topo.ts` 单测（含一个造环用例）；手写一个 mock `run-claude` 跑通 `io`+`manifest` 读写。

## Phase 2 · 先行弹（Tracer Bullet）：打通 Source → Survey → repo-map.json

**目标**：最小代价验证"最不确定的部分"——`claude -p` 子进程真的能按只读权限读源码、产出符合 schema 的 JSON。其余 6 stage 暂留桩。

1. **`prompts/surveyor.md`** —— Surveyor 角色 prompt（只如实记录结构、不臆测、输出严格符合 `repo-map.json` schema、附 schema 定义 + 示例）。
2. **`src/agents/surveyor.ts`** —— 拼用户 prompt（"扫描 `work/source/`，写 `work/repo-map.json`"）+ 调 `run-claude({role:'surveyor', readOnly:true, cwd: runDir})`。
3. **`src/stages/01-acquire.ts`** —— 无 agent：URL → `git clone --depth 1 <url> work/source`；本地 → manifest 记 `sourcePath`，跑 agent 时用 `--add-dir`。失败 → manifest `failed`。
4. **`src/stages/02-survey.ts`** —— 调 surveyor agent，manifest 翻 done。
5. **`src/orchestrator.ts`（最小版）** —— `run(repo, opts)`：建 runDir → 初始化 manifest → 跑 acquire → 跑 survey → 其余 stage 暂 `notImplemented` 占位但能干净退出。
6. **`src/bin/atlas.ts`（最小版）** —— 解析 `atlas run <repo>` → 调 orchestrator。

**Phase 2 冒烟（真实 `claude`，花你的 token）**：拿一个小仓库（如 `https://github.com/yyx990803/@vue/reactivity` 或本地一个几文件的 ts 项目）跑 `bun run src/bin/atlas.ts run <repo>`，确认：
- `atlas/{key}/work/source/` 克隆到位 / 本地路径无改动（`git status` 验证 NFR-2）。
- `work/repo-map.json` 产出且 schema 对。
- `manifest.json` 里 acquire/survey = `done`、记了真实 `claude -p` 命令（AC-7 可核验含 `--allowedTools Read,Glob,Grep`）。

**先行弹通过 = 集成风险消除**，再铺开其余 stage。

## Phase 3 · 铺开剩余 Stage / Agent / Prompt

逐个补齐（每个 stage 内部对齐 design §4 的契约）：

- **`prompts/architect.md` + `prompts/critic-outline.md`** + `agents/architect.ts` + `agents/critic.ts`（critic 通用，靠参数切 outline/chapter 模式）→ **`stages/03-outline.ts`**：Architect 出 `outline.json` → `topo.ts` 算 `topoOrder` → Critic 对抗评审（≤2 轮，design §6）。Critic 用同一 `topo.ts` 复算交叉校验自底向上（design §7）。
- **`prompts/reader.md`** + `agents/reader.ts` → **`stages/04-research.ts`**：每章一个 Reader，`pool.ts` 并发 4，产出 `work/chapters/{slug}/research.md`。
- **`prompts/writer.md` + `prompts/critic-chapter.md`** + `agents/writer.ts`（复用 critic agent）→ **`stages/05-write.ts`**：Writer 写 `draft.md` + `replica/*.ts|js` → Critic 评审（design §5.4 四条验收）→ ≤2 轮。
- **`prompts/assembler.md`** + `agents/assembler.ts` → **`stages/06-assemble.ts`**：拷 `draft.md` → `site/guide/{nn}-{slug}.md`（nn=topo 序号）；生成 `.vitepress/config.ts`（侧边栏按 layer 分组 + topo 序，design §11）、`index.md`、`package.json`（pin vitepress）。`config.ts` 用字符串模板生成，site 自包含（ADR-0006）。
- **`stages/07-build.ts`**：`cd site && bun install && bun run docs:build`，失败标 `failed` 但保留 `site/`（design §15），`--skip-build` 可跳。

**Phase 3 冒烟**：完整 `atlas run <repo>` 跑通到 `site/`；`cd atlas/{key}/site && bun install && bun run docs:build` 成功产 `dist/`（AC-1）。

## Phase 4 · CLI 补全 + 续跑 + 收尾

- **`bin/atlas.ts` 补全**：`resume/list/clean/show` + 全局 flag（`--concurrency`、`--review-rounds`、`--skip-build`、`--model`、`--from`、`--only`、`--force`）。
- **续跑逻辑**：`resume` = 读 manifest → `nextPendingStage` → 从那继续；`--from`/`--only` 覆盖选择；`--force` 重置目标项为 `pending`（design §9）。
- **错误处理/降级**：agent 失败 → manifest `failed` + stderr 摘要，不无限重试；评审到上限 → `accepted-with-warning`；章数超 `maxChapters` 拦截（design §15）。
- **`README.md`** 更新：状态从"待实现"改为带用法；补一个最小 quickstart。
- **端到端验收脚本/手册**（`docs/` 或 README 附录）：覆盖 AC-1~AC-7 的核验步骤（含本地源的 `git status` 不变性、只读 flag 核验、自底向上拓扑校验）。
