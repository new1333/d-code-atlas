# 让全书脉络图用 mermaid 渲染（接入 vitepress-mermaid-renderer）

## 背景诊断
脉络图的 markdown 侧已经"想用 mermaid"了——`06-assemble.ts:generateMermaidGraph` 会程序化生成 mermaid 块，`ensurePrologueGraph` 兜底拼进 prologue。但有两个断点：
1. **VitePress 站点没有渲染 mermaid 的能力**：`atlas/*/site/` 只有 `config.ts`，没有 `theme/index.ts`，`package.json` 也没装渲染依赖。mermaid 块被当代码块显示成源代码文本。
2. **提示词自相矛盾**：`synthesizer.md:63`、`synthesizer.ts:64` 还说"用 ASCII 图 / 文字流程 / 简表"，与"程序化 mermaid"的实现打架，导致 LLM 画 ASCII 后被兜底逻辑反复处理。

决策（已确认）：① 图**只用程序化 mermaid**，LLM 不再画图；② 插件由 **Assembler 生成 + Stage 兜底校验**（与现有 `search` 处理方式一致）。

## 改动清单

### 1. `src/prompts/synthesizer.md`（消除矛盾 + 说明渲染载体）
- §4.1 第 62-65 行「全书脉络图」块：改为「**你只写一段引言，不要自己画图**——编排层会依据 `outline.dependsOn` + `topoOrder` 程序化生成一张 mermaid 依赖图插入本节。你的引言要点出：图怎么读（箭头=前置→后继）、最显眼的根节点/汇聚点是哪章、有哪些跨 layer 的关键边」。自检清单第 1/5 条与硬约束第 3 条的「脉络图」措辞同步改为「脉络图引言」。

### 2. `src/agents/synthesizer.ts`（user prompt + validate 同步）
- 第 64 行任务第 5 条：从「画全书脉络图（ASCII/文字/简表）」改为「为全书脉络图写一段**引言**（图本身由编排层程序化生成，你只写引言）」。
- 产物结构第 71 行「全书脉络图」→「全书脉络图（引言；mermaid 图由编排层注入）」。
- `validate`（第 92-102 行）保持校验前三块 H2——第四块本就不强制（脉络图由程序注入），逻辑不变。

### 3. `src/prompts/assembler.md`（生成 mermaid 渲染脚手架）
- §4 产物树（第 29-39 行）补一个文件 `site/.vitepress/theme/index.ts`。
- §4.2 之后新增 **§4.2b `site/.vitepress/theme/index.ts`（mermaid 渲染）**：要求 Assembler 生成固定内容（调 `createMermaidRenderer({ theme: isDark.value ? 'dark' : 'default' })`，并在 `nextTick` + `watch(isDark)` 时重新初始化；内容来自插件 README）。
- §4.4 `package.json`（第 109-123 行）：`devDependencies` 在 `vitepress` 之外，加 `vitepress-mermaid-renderer`（pin 一个具体版本，如 `^1.1.28`）与 `mermaid`（peer 依赖，pin `^11.0.0`）。
- §5.2 自检清单第 4 条（工程可构建）：追加「`.vitepress/theme/index.ts` 存在且 `import { createMermaidRenderer } from 'vitepress-mermaid-renderer'`」。
- §6 硬约束补一条：「`package.json` 必须含 `vitepress-mermaid-renderer` 依赖；必须生成 `.vitepress/theme/index.ts` 启用 mermaid 渲染（否则脉络图显示为源码）」。

### 4. `src/agents/assembler.ts`（user prompt + scaffoldFiles 校验）
- user prompt 的「任务第 4 步（生成 package.json）」补一句：`devDependencies` 含 `vitepress-mermaid-renderer`（pin 版本）与 `mermaid`（peer，pin `^11`）。
- user prompt 的「任务」新增一步：生成 `site/.vitepress/theme/index.ts`，内容固定（给完整代码模板），用途是「渲染 markdown 中的 mermaid 块（全书脉络图）」。
- 自检项追加「⑦ mermaid 渲染就绪：`.vitepress/theme/index.ts` 存在且 import 了 `createMermaidRenderer`」。
- `scaffoldFiles`（第 148-152 行）：追加 `joinPath(site, ".vitepress/theme/index.ts")`，让现有 `validateScaffold` + 兜底核验自动覆盖（与 `config.ts`/`index.md`/`package.json` 同等待遇）。

### 5. `src/stages/06-assemble.ts`（站点结构校验 + 兜底）
- 结构校验段（第 194-199 行附近）：在检查 `configTs`/`indexMd`/`pkgJson` 之后，追加 `const themeTs = joinPath(site, ".vitepress/theme/index.ts")`，`if (!(await pathExists(themeTs))) errors.push(\`缺 ${themeTs}\`)`。
- 兜底：若 Assembler 没生成 `theme/index.ts`（极端情况），程序化补写一份固定模板（与 `ensurePrologueGraph` 补脉络图同思路，保证不阻断 build）。这是双保险，可选但推荐。

### 6. `test/stages.test.ts`（同步测试）
- `makeAssemblerSpawn`（第 789-833 行）：mock 落盘时追加写 `site/.vitepress/theme/index.ts`（写一行含 `createMermaidRenderer` 的内容即可过校验）。否则现有 `06-assemble` 成功测试会因新增校验而失败。
- 「成功」测试（第 835 行起）：追加 `expect(await pathExists(joinPath(site, ".vitepress/theme/index.ts"))).toBe(true)`。
- 「结构不全（缺 config.ts）」测试（第 883 行起）逻辑不变（它本来就缺脚手架，仍走 failed）。
- 若 §5 加了兜底补写，补一个用例验证「Assembler 漏 theme/index.ts → stage 程序化补写 → done」。

## 不改的部分
- `generateMermaidGraph` / `ensurePrologueGraph`：mermaid 块的生成与注入逻辑正确（已单元复现），保持不动。
- `07-build.ts`：`bun install` 会自动装上新增依赖，无需改 build stage。
- 现有 site 产物（`atlas/mitt/site/` 等）：不回填，等下一次 run 自然带上；或需要时单独重跑 assemble。
