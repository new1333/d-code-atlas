把发布订阅退化成一张查找表 ​

如果你写过 Node 后端，或者在前端用过 addEventListener，那 EventEmitter 这类东西你多半碰过。它能干的事不少：给监听器排优先级、标记只触发一次、监听器太多时报警、还能异步派发。能力一长串，内部状态也跟着一大堆。

可多数时候，你想要的其实很简单：A 模块通知一句「数据好了」，B 模块听见了去做事。就为了这一句，你 new 了一个 EventEmitter，它肚子里塞着优先级队列、Symbol 钩子、各种计数器。你想看一眼自己到底注册了哪些监听器，得翻它的 API，还看不全。

mitt 把这件事整个翻过来：它把一个事件发射器削到只剩一张表。这张表就是它的全部家当，console.log 打出来，所有订阅关系一览无余。这一章我们从零把这张表搭起来。

两块最小的积木 ​

搭表之前，先看清两样最底层的东西。

第一块是事件类型，说白了就是一个名字。它只能是字符串或 symbol。你可以当成一个频道名：谁要听这个频道，就盯着这个名字。

第二块是处理器，一个收数据的函数。频道里有动静，所有盯着它的处理器就被挨个叫起来，把那份事件数据递过去。

就这两样。mitt 没在这里用类，也不搞继承。一个名字，加一个收到数据就跑的函数。

把同一频道的处理器装进一个数组 ​

一个频道往往不止一个人在听。'login' 这个频道，可能有人负责写日志，也有人负责发欢迎邮件。所以每个频道底下，得有个东西把这些处理器都装起来。

mitt 的选择简单到有点愣：就用一个普通数组。不做成带优先级的队列，也不用 Set 去重。

为什么这么「裸」？因为这章的目标就是透明。数组长什么样，表里就长什么样，没有中间层替你做决定。

一张表装下所有频道 ​

把上一节的「频道 → 处理器数组」复制很多份，每份对应一个频道，再找个东西全收起来。mitt 用的就是一个 Map：键是事件类型（频道名），值是这个频道下的处理器数组。

这就是发射器的全部状态。除此之外，发射器里再没有第二个东西藏着。

把这张表当成一块公共留言板：每个频道是板上的一块分区，分区里钉着一张纸条，列着一串「听到动静要做的事」。谁来都能看见整块板。

三步走完所有操作 ​

发射器一辈子就干三件事，而且每一件都只是在读写这块留言板。

订阅（on）是往表里塞一条。先查表里有没有这个频道，有就把新处理器 push 进它的数组，没有就新开一条记录。

发布（emit）是从表里取出来逐个叫醒。查表拿到这个频道的处理器数组，从头到尾挨个调用，把事件数据递给每一个。发布只是读表，表本身一个字都没改。

退订（off）是从表里抹掉一条。查表拿到数组，把那个处理器移除。

三件事都围着同一张表转，没有别的状态，也没有隐藏的副本。

亲手写一个 ​

下面是从零写的最小实现，三十来行，每一行都对应上面某个动作。我故意用最朴素的写法：普通 if、普通 push、普通 splice、普通 for，不为体积或技巧做优化，唯一目的是让你看清「表就是全部」。

js
// emitter.mjs —— 存成文件后 `node emitter.mjs` 即可运行
function createEmitter() {
  const all = new Map();       // 这张表，就是发射器的全部状态

  return {
    all,                       // 把表公开出来：拿到发射器的人都能直接看、直接改

    on(type, handler) {        // 订阅 = 写表
      const handlers = all.get(type);
      if (handlers) handlers.push(handler);
      else all.set(type, [handler]);
    },

    off(type, handler) {        // 退订 = 删表
      const handlers = all.get(type);
      if (handlers) {
        const i = handlers.indexOf(handler);
        if (i !== -1) handlers.splice(i, 1);
      }
    },

    emit(type, evt) {           // 发布 = 读表
      const handlers = all.get(type);
      if (handlers) for (const h of handlers) h(evt);
    },
  };
}

跑一段场景：

js
const emitter = createEmitter();
const a = (n) => console.log('a 收到', n);
const b = (n) => console.log('b 收到', n);

emitter.on('foo', a);
emitter.on('foo', b);

console.log(emitter.all);   // Map { 'foo' => [ [Function a], [Function b] ] }

emitter.emit('foo', 42);    // a 收到 42 / b 收到 42

console.log(emitter.all);   // 还是 Map { 'foo' => [a, b] }，发布前后表没变

最后一行值得记住：发布前后，表没有任何变化。派发纯粹是在读表，不产生新状态。

关键权衡：为了「只剩一张表」，砍掉了什么 ​

原理演示只用了三十来行，但 mitt 真正值钱的是它主动放弃的那些东西。下面三条，每条都是「做了什么选择、换来什么、代价落在哪」。

权衡一：让一张 Map 成为唯一状态 ​

选择：发射器的全部状态就是一张 Map<事件类型, 处理器数组>，没有第二个字段，没有优先级队列，没有调度器。

换来：整个发射器能用一句话讲完，「它就是一张表」。这张表能被 console.log 直接打印，订阅关系一目了然，代码体积也压到极致（mitt 宣称压缩后约 200 字节）。这里选 Map 而不是普通对象也有道理：Map 能直接拿 symbol 当键，没有原型链污染，遍历顺序就等于插入顺序，状态可预测。（这是从设计反推的判断，源码没留注释明说。）

代价：放弃封装。这张表对任何拿到发射器的人都完全公开、完全可变，谁都能 emitter.all.get(...) 偷看，也能 emitter.all.set(...) 直接改。「能窥探」和「能被随便篡改」在这里是一体两面。至于 mitt 为什么索性把它做成实例上的公开字段、甚至允许从外部塞一张表进来共享，那是下一章《函数工厂与无 this 的方法》专门要讲的取舍，这里先把「唯一状态容器」这一面立起来。

权衡二：事件类型刻意不标准化 ​

选择：事件类型只接受字符串和 symbol，而且刻意不做任何标准化：不转小写、不去空格、不统一格式。

换来：精确匹配的语义完全可预测。你注册的是 'foo'，就只有 emit('foo') 能叫醒它，所见即所得，不会有「框架偷偷帮你转了大小写」的意外。

顺带一个副产品：symbol 天然形成私有频道。你拿一个 Symbol() 当频道名，只要这个 symbol 的引用没泄露，外部代码就永远没法订阅或触发这个频道，它像一把只有你持有的钥匙。

代价：键的一致性责任整个甩给了调用方。'FOO' 和 'foo' 在 mitt 眼里是两个互不相干的频道，注册 'FOO' 却去 emit('foo')，不会报错，就是没人理你。这不是 bug，是写进基因里的设计。

权衡三：处理器集合用裸数组 ​

选择：每个频道下的处理器就是一个普通 Array，不内置优先级，不内置 once，不内置异步队列。

换来：极小的体积，加上完全透明的状态语义。表里写什么，运行时就按什么跑，没有隐藏的调度层替你重新排序或延迟。

代价落在调用方这边：去重和「只触发一次」这些事得自己管。off 用 indexOf 找回调，意味着同一个函数你注册两次，它会被当成两条不同的记录，退订时只删一条，剩下的还在。想要「只触发一次」也没有 once 参数，得让处理器在执行体里把自己退订掉：

js
const once = (type, handler) => {
  const wrapper = (evt) => {
    handler(evt);
    emitter.off(type, wrapper);   // 干完把自己摘掉
  };
  emitter.on(type, wrapper);
};

多数场景下你根本用不上优先级和 once，也就根本不用为它们付代价。mitt 把「需不需要这些能力」这个决定权，连同实现成本，一起交还给了你。

小结 ​

这一章立起一块地基：一个事件发射器，可以小到只剩一张 Map<事件类型, 处理器数组>。

三块积木：事件类型（string | symbol）、处理器（收数据的函数）、装处理器的数组。一个容器：一张 Map，是发射器的唯一状态。三步操作：订阅写表、发布读表、退订删表，都围着这一张表转。

围绕「把状态压成一张表」这个选择，我们看清了三笔交易：用一张 Map 换极简与可窥探，代价是放弃封装；用不标准化键换精确匹配与 symbol 私有频道，代价是把一致性甩给调用方；用裸数组换透明语义，代价是去重和 once 得自己造。

这张表已经能跑了，但它现在还只是被关在一个函数里的一块内存。它凭什么能被公开成实例字段、凭什么能让两个发射器共享同一张表、那些方法又凭什么不需要 this 就能工作，是下一章《函数工厂与无 this 的方法》要解开的扣。
