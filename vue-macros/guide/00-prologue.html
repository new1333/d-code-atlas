导读：vue-macros 源码解读 ​

这本书在讲什么：一句话主线 ​

你打开这本 Atlas，多半是因为写过 Vue、用过 defineProps / defineEmits，然后某天装了一个叫 vue-macros 的库，发现突然能用 defineModels、shortEmits、$ref、JSX 上的 v-if 这些更顺手的写法，心里嘀咕过一句「这玩意到底怎么做到的」。这本 Atlas 要回答的不是「这些宏分别能做什么」——那种事查文档就行——而是「一个有 30 多个宏的库，到底是怎么从无到有搭起来的」。

把全书压成一句话主线：

vue-macros 的全部宏都是编译期改写器——在源码送进 Vue 编译器之前，把更顺手的写法翻成 Vue 原生形态，运行时一尘不染；围绕这条范式，它把「懒解析 + 偏移增量编辑」收成一块公共底座、把「门控 + 物化」收成分发层、把「同一特性拆前后两段」收成管道规则，再用虚拟模块、IDE 镜像、框架回收三套外延机制，把改写边界推到运行时、编辑器、宿主框架三个外部世界。

这句话怎么落到各 layer：

  • primitive 三章（第 1-3 章）搭地基：怎么拆 SFC、怎么改字符串不破坏 sourcemap、怎么让一份转换在六套构建器里都跑、怎么用磁盘上不存在的虚拟模块装载运行时 helper。这三件事不做完，后面所有宏都得各自重发明一遍。
  • composite 九章（第 4-12 章）讲具体宏：每个宏都是同一条「编译期改写」的不同化身——有的是纯翻译（props/emit 重写、JSX 指令、语法垫片），有的多了类型求值（defineModels、better-define），有的要碰赋值语义（reactivity-transform），有的要打开 SFC 的文件边界（结构扩展、模板/渲染重定向），有的在搬运语句（静态提升、export 重写）。
  • system 四章（第 13-16 章）讲怎么把这些宏装成一个系统：版本感知的开关表、写死顺序的转换管道、给 IDE 看的影子实现、接到 Nuxt/Astro 等宿主框架里的回收模式。

这条主线的精髓不在「30 多个宏各做什么」，而在「它们共用同一套机制、各自的复杂度都花在边界上」。

怎么读这本书：两条阅读路线 ​

线性路线（按 topoOrder） ​

按章号从前往后读，每一章承接前一章的地基、打开下一章的问题：

  1. SFC 解析与增量 AST 编辑 — 立两根柱子（懒解析 + 偏移编辑），所有后续宏都站在这上面。
  2. unplugin 多构建器适配 — 把改写逻辑包成纯函数，让一份内核自动生成六套构建器外壳。
  3. 虚拟 helper 模块 — 用 resolveId / loadInclude / load 三件套，让磁盘上不存在的模块也能被 import 进来。
  4. props/emit 宏重写 — 第一次见「编译期翻译官、运行时零新增」这条范式在最朴素的形态里走一遍。
  5. defineModels — 把同一条翻译再推一步：从一份类型同时合成 props 与 emits，再加运行时粘合。
  6. better-define — 在编译期重造半个类型求值器，把 TS 类型降级成 Vue 运行时校验对象。
  7. 响应式语法糖 — 用静态改写换「无 .value」的书写体验，代价是赋值语义被侵入。
  8. SFC 结构扩展 — 松开「一个 SFC 一个 script setup」的铁律，最重的 setup-component 用虚拟 SFC + 闭包子弹穿透 import 边界。
  9. JSX 指令 — 不发明新运行时，靠分桶遍历把 v-if / v-for 翻译成等价 JSX 表达式。
  10. 模板与渲染重定向 — 把渲染来源从 <template> 扩展到 JSX / h() / 命名模板，跨 pre/post 两阶段改写。
  11. 静态提升与 export 重写 — 用保守的静态判定把常量搬到模块顶层，把 export 翻译成 Vue 宏。
  12. 语法垫片 — 抹平 Vue 版本差异：模板层借编译器挂号、脚本层独立改写。
  13. 统一配置体系 — 把 30 多个特性收进一张版本门槛表，默认值 = Vue 版本的函数。
  14. 主聚合管道 — 把所有宏按写死的顺序串成一条管道，「顺序即语义」。
  15. volar IDE 镜像 — 给每个宏再写一份只产类型的影子实现，让编辑器也认得自定义宏。
  16. 框架集成 — 用「拆-注-插回」把 vue-macros 接到 Nuxt/Astro/DevTools，转换内核一行不改。

按主题路线 ​

针对常见阅读目标，挑对应的章节子序列：

  • 想搞懂「一个宏从无到有怎么写」：1 → 2 → 3 → 4 → 13 → 14。这条线把「写一个宏」涉及的所有公共设施全过了一遍。
  • 想搞懂「类型怎么落到运行时」：4 → 5 → 6。三章形成一条「重写 → 合成 → 降级」的递进。
  • 想搞懂「虚拟模块机制的所有化身」：3 → 5（注入 helper）→ 8（虚拟 SFC）→ 10（命名模板）。同一机制装载不同形态的东西。
  • 想搞懂「双向绑定的所有姿势」：5（runtime 模式 vs reactivity 模式）→ 7（赋值即 .value 的更普适版本）。
  • 想搞懂「JSX 写 Vue」全图：9（指令翻译）→ 10（define-render / export-render 把 JSX 当渲染来源）。
  • 想搞懂「宏怎么和 Vue 编译器协作」：8（scan / transform / load / postTransform 四阶段）→ 10（preTransform / postTransform 两阶段）→ 12（A 类挂号进 Vue 的 nodeTransforms）→ 14（Vue 编译器是管道的分水岭）。这条线解释了「为什么有些宏必须拆成两半」。
  • 想搞懂「响应式语法糖的前世今生」：7（赋值即 .value）→ 5 的 reactivity 模式那一节（同一思想被 defineModels 复用）。
  • 想搞懂「IDE 怎么认识宏」：15 单章即可，但建议先读 4、5、9 知道 transform 端在做什么，再读 15 看影子是怎么对齐的。
  • 想搞懂「接到 Nuxt / Astro 这种宿主框架」：14 → 16。先知道管道长什么样，再知道它怎么被回收进宿主。
  • 只想看「全书精华、最薄路径」：1 → 4 → 5 → 14。这四章足以让你抓住「编译期改写 + 管道编排」的命门。

贯穿全书的核心原理 ​

这些原理不是某一章的私有财产，它们在多章以不同化身反复出现。一旦认出它们是同一个，理解就贯通了。

原理一：编译期改写、运行时零新增。 这是全书的范式本身。一个宏可以引入新写法（$defineProps、ShortEmits、defineModels、$ref、JSX 上的 v-if、export const、<Comp foo>），但不引入任何新的运行时能力——所有写法在编译期就被翻译成 Vue 早就认识的形态。现身于：第 4、5、7、9、10、11、12 章，每章是这条范式的不同化身。

原理二：懒解析 + 偏移增量编辑。 第 1 章立的两根柱子——解析时不建树、谁用谁按需取（再叠一层内容缓存）；所有改写登记成「在文档第 N 到 M 字符处增删改」，靠 magic-string 保住 sourcemap、还让多个宏共用一份编辑缓冲。后续所有「在 script setup 里改东西」的宏都直接踩在这块地基上。现身于：第 4、5、7、9、10、11、12 章，以及第 8 章 setup-block 的标签改名。

原理三：虚拟模块桥接编译期与运行时。 宏在编译期往源码插一句 import，但目标路径磁盘上不存在——靠 resolveId / loadInclude / load 三件套拦下 id、就地返回代码。同一机制装载三种不同的东西：单个 helper 函数（第 5 章 defineModels 的 useVModel）、完整的合成 SFC（第 8 章 setup-component 的虚拟子组件）、可复用的模板片段（第 10 章 named-template）。现身于：第 3 章（立）→ 第 5、8、10 章（用）。

原理四：「门控 + 物化」的开关哲学。 一个特性是开着还是关着，由配置项决定——关的直接返回 undefined、连插件都不物化；开的按当前构建器物化出对应外壳。这套模式最早在第 2 章的 resolvePlugin 出现，第 13 章升级成「版本号当默认门槛」，第 14 章又把它复用为管道里「配置即开关」的中枢。现身于：第 2、13、14 章。

原理五：同一特性拆前后两阶段。 Vue 编译器是一道分水岭——它之前的宏看到的是「源码 / script setup 块」，它之后的宏看到的是「渲染函数 / createVNode 调用」。一个特性要干预两次（先改源码形态、再改编译产物），就得拆成两个插件实例，分别放在分水岭前后。现身于：第 8 章 setup-component 的 scan/transform/load/postTransform、第 10 章 named-template 的 preTransform/postTransform、第 14 章把它抽象成「同一特性拆前后两段」的通用规则。

原理六：「一份源、两个消费者」的镜像。 同一份 .vue 源码，运行时引擎和编辑器是两个互不通气的消费者——前者走 transform 那条线、产出能跑的代码；后者走语言服务那条线、读合成的虚拟 TS 代码。所以每个宏要在两条管线上各写一份实现：transform 端写改写器、volar 端写「只产类型」的影子。广义上看，第 12 章 A 类宏「挂号进 Vue 编译器的 nodeTransforms」也是同一种思想——不自己改源码、借别人的管线。现身于：第 15 章（IDE 与运行时镜像）、第 12 章（借 Vue 编译器而非自造）。

原理七：「回收而非重建」的集成哲学。 当 vue-macros 接到一个已经装好官方 Vue 插件的宿主框架（Nuxt、Astro），它不重新建一份 Vue 插件，而是把官方那份从框架的 plugins 数组里拆出来、喂回自己管道末尾的槽位、再插回原索引位——保住框架对插件做的所有专属配置，又让全局只有一份 Vue 插件。这条只在第 16 章出现一次，但它是「集成层只做装配与上下文注入、内核不动」这种通用哲学的范本。

读这张图的关键：

  • 第 1 章是地基的地基——composite 九章里有八章直接依赖它（只有第 6 章透过第 4 章间接依赖）。读懂第 1 章，就读懂了所有「在 setup 里改东西」的宏的一半。
